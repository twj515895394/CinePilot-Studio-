# 第四轮 Grill：剧本场次与导演片段的对应关系

> 日期：2026-10-30
> 状态：第三轮与第四轮方案 B 均已确认；第五轮另见新讨论记录
> 依据：[CONTEXT.md](../../CONTEXT.md)、[ADR-0003](../adr/0003-optional-single-level-subsegments.md)
> 讨论规范：[grill-with-docs](../process/grill-with-docs/SKILL.md)

## 1. 已确认的前置约束

```text
项目 → 分集（即一条独立短视频）
      → 片段 → 镜头
             或
      → 片段 → 子片段 → 镜头
```

- 片段下子片段可选，但至多一层。
- 同一片段不能同时包含直属镜头和子片段。
- 每个镜头只归属一个最末级内容容器。
- 与创意点子、分集的关系已分别在 ADR-0001、ADR-0002 中确认。
- 本轮不讨论片段/镜头的文件存储与数据表细节。

## 2. 第四轮（已确认）：术语与阶段交接边界

**剧本场次（Screenplay Scene）**：文学剧本内独立标识的一场戏，是**创意编剧**输出；具体按何种标准分场尚待决定。

**导演片段（Segment）**：影视制作阶段使用的分集内容单位，**与剧本场次独立建模**。

**场景资产（Location/Set Asset）**：候选含义为可复用的视觉环境/地点设定（如「公司会议室」）；它与剧本场次并非同一种对象，但其正式归属与共享模型仍未决定。

这三者是否属于独立概念、如何对应，会影响两大业务系统之间 handoff 的版本追溯。

### 具体例子

剧本场次 S03：「狗狗在会议室被误会，最终找出偷拿文件的同事」，发生于同一地点，包含两个戏剧节拍。

导演将它拆为：

- 片段 P05：「被误会」，镜头 10–13；
- 片段 P06：「追查与反击」，镜头 14–18。

当 S03 修改时，系统需要能定位 P05 和 P06 的来源和潜在受影响范围；不能只通过对话摘要推测。

### 候选决策

**A. 场次 = 片段，强制一一对应**：容易理解和实现，但把文学剧本结构直接锁死成导演镜头分组；剧本中的一场不能分拆成多个导演片段。

**B. 独立建模、场次一对多映射片段（推荐）**：一个剧本场次可拆为多个导演片段；每个导演片段引用一个明确的源剧本场次。支持拆分、保留可追溯性，暂不支持一个导演片段跨多个源场次。

**C. 独立建模、场次与片段完全多对多**：一场可拆多片段，一片段可汇集多个剧本场次，适配复杂蒙太奇和跨场次剪辑；映射管理和变更影响判定成本更高。

**推荐 B 的边界**：它是分集内两大阶段产物的来源关系，不决定「场景资产」如何复用；如遇跨场次蒙太奇，可拆片段或未来升级多对多关系。

## 3. 未确认事项（本轮不扩展提问）

- 剧本场次如何定义：强制换地点/时间才切场，还是按戏剧节拍自定义？
- 一段镜头是否可引用多个剧本场次作为参考？
- 剧本的结构与场景资产如何映射、是否允许同场景资产多个场次共用？
- 所有片段是否必须有来源场次，还是创作早期存在未关联的导演草稿？
- 文学剧本改动后，如何提示、重建、部分重审导演片段及镜头。

**第四轮已确认 B（2026-10-30）**：剧本场次与导演片段独立管理，剧本场次可拆为多个导演片段；每个导演片段关联且只关联一个明确来源场次，两者隶属同一分集。已更新 [CONTEXT.md](../../CONTEXT.md)，并新增 [ADR-0004](../adr/0004-screenplay-scene-to-director-segment.md)。

**仍待讨论**：源场次必须在草稿期间就绑定，还是只在定稿时强制；剧本场次的划分标准；来源版本及变更影响评估策略。

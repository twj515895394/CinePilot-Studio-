# 第十轮 Grill：Agent 跨阶段正式交接读取什么上下文

> 日期：2026-10-30  
> 状态：第九轮方案 A 已确认；本轮仅为候选方案  
> 规范：[grill-with-docs](../process/grill-with-docs/SKILL.md)  
> 依据：[需求基线](./0001-initial-scope-and-design-tree.md)、[ADR-0005](../adr/0005-independent-concepts-before-episode.md)、[ADR-0007](../adr/0007-approved-artifact-revision-policy.md)、[ADR-0008](../adr/0008-review-dependent-artifacts-without-auto-regeneration.md)、[ADR-0009](../adr/0009-approved-upstream-stage-gates.md)

## 1. 为什么这是关键问题

用户要求创意编剧系统和影视制作系统通过 Agent + Skill 对话产出内容、由用户定稿，并在系统中持久化、查看和回溯。九轮已决定：正式阶段基于上游已定稿产物推进，且分集独立；但是**下一阶段 Agent 到底如何获得正确版本的资料**尚未决定。如果只靠聊天历史，长链路会超出上下文；只靠上一份 Markdown，又可能丢失角色设定、用户选择理由和世界观约束。

本轮只确定**正式 Handoff 的资料来源原则**，不确定具体文件 schema、Token 压缩算法、Skill 路由实现，也不增加外部 MCP/API 集成。

## 2. 场景压力测试

EP07 已完成故事大纲 v4 和剧本 v3 定稿。你现在说「进入导演阶段，先设计角色表演、片段和镜头」；期间已经在 Agent 中来回聊过 40 轮，创意方向最初确认为“荒诞喜剧”，项目还有角色外观、世界观与分集风格限制。

导演 Agent 应拿到哪些资料？如何确保以后再打开 EP07，不论聊天窗口是否还在，都能知道当时选择的角色风格、剧本 v3 和具体导演任务？

## 3. 候选方案

### A. 把所有历史聊天记录给下一阶段 Agent

优点：完整保留对话探索过程，可能包含细微意图。
缺点：Token 成本高，包含大量被否决的草稿与旧决策，也容易让 Agent 将早期设想误认为当前定稿；长期难扩展。

### B. 系统组装精简的正式 Handoff 资料包（推荐）

正式 Handoff 由系统生成，至少包含以下**类别**：

1. **任务定位**：当前项目、分集、目标阶段以及用户这次要完成的目标。
2. **定稿来源**：应读取的上游已定稿产物及其**确切版本**，不把草稿当成正式输入。
3. **必要创作约束**：选定创意方向、角色设定、整体风格、时长及用户确认的限制（实际必需项由阶段合同决定）。
4. **当前决策摘要**：已确认的关键意图与禁改事项，明确哪些是有效约束，而不是完整聊天日志。
5. **目标产物合同**：该阶段应提交哪些内容、需要符合哪些质量或结构校验（详细规则待后续另行讨论）。

Agent 可以按需再读取指定的上游原文、项目文件或已确认记录；完整聊天历史保留给用户查看，但**不默认整包投入下阶段上下文**。

优点：对话长短不影响交接；输入可回溯，Token 更可控，并能让不同专业 Skill 在一致的上下文基础上工作。

代价：必须有一个系统代码控制的组装和校验入口，不能只凭某个 Router Skill 口头约定。

**实现节制**：B 只要求有版本明确的可重建 Handoff，不必首期建设复杂 Agent 记忆系统。是否采用 JSON manifest、Markdown 摘要、SQLite 索引等格式应留给存储设计轮次。

### C. 只向下一阶段 Agent 提供最近一个已定稿文档

优点：最简单。
缺点：容易漏掉经确认的跨阶段设定、角色规范和项目级限制；需要用户多次重复，回到过去的手工补充上下文工作方式。

## 4. 跨边界提醒

- **点子/创意方向早于分集创建**：应明确区分“选定创意方向并创建分集的初始化输入”与“分集内正式阶段 Handoff”。本轮只讨论后者原则。
- **待复核不是自动重做**：如上游新版本导致下游待复核，不能让 Handoff 自动触发重新生成；是否允许用户明确沿用旧版待后续继续决策。
- **两个系统不一定需要两个 Agent**：本轮不决定是一个 CLI Agent 按阶段切 Skill，还是多个专职 Agent；只讨论所需上下文。

## 5. 第十轮唯一问题

**你希望下一阶段 Agent 的正式交接资料从哪里来？**

- **A**：完整聊天历史直接传入。
- **B（推荐）**：系统依据定稿版本、项目/分集约束、关键已确认决策与目标产物要求组装精简 Handoff，按需补充原文。
- **C**：仅传上个阶段的最新已定稿文档。

本轮确认后再更新领域术语和 ADR；目前 B 仅是建议，不等于已决定。

# 第二轮确认与第三轮问题：分集内容层级

> 日期：2026-10-30
> 状态：第二轮确认；第三轮待用户回答
> 依据：[CONTEXT.md](../../CONTEXT.md)、[ADR-0001](../adr/0001-idea-to-work-derivation.md)、[ADR-0002](../adr/0002-episode-is-independent-work.md)
> 讨论规范：[grill-with-docs](../process/grill-with-docs/SKILL.md)

## 1. 已确认：分集就是独立作品（第二轮选择 A）

- 一个项目可包含多个分集；**每集对应一条独立完整短视频**，拥有自己的剧本和影视制作规划。
- 「独立作品」只是「分集」的别称，不另设 `作品 → 分集` 的中间容器。
- 不要求分集之间存在连续剧情；同一创意点子可成为不同分集的主创意来源（第一轮 B）。
- 此处定义的是**创作单位**，不是已生成的视频媒体文件；首期视频生成不接入。

### 1.1 为什么不选其他方案

- **未选 B（项目 → 作品 → 分集）**：主要服务于一部连续作品包含多个发布集，目前会给“一条短视频一部完整剧本”增加无意义中间身份。
- **未选 C（独立作品与系列并存）**：后续可以按需求增加可选系列/合辑组织，但不宜在首期提前引入多种内容容器。
- 这属于难以逆转的核心领域身份选择，因此归档 [ADR-0002](../adr/0002-episode-is-independent-work.md)。

## 2. 第三轮待决定：片段、子片段与镜头如何组织？

在 `项目 → 分集` 后，用户希望能够浏览和修改分集内的片段、子片段和分镜。必须澄清**子片段是否必选、层级是否固定、镜头只能归属何处**，否则后续 Agent 输出 schema、Web 树控件、镜头排序会出现冲突。

### A. 全部固定层级

`分集 → 片段 → 子片段 → 镜头`，即使一段只有一个镜头也必须创建子片段。简单直接但容易产生空壳子片段；短视频规划会显得繁琐。

### B. 可选单层子片段（推荐）

`分集 → 片段 → 镜头` **或** `分集 → 片段 → 子片段 → 镜头`。

- 「片段」是分集内可排序的结构单位；简单片段直接有镜头。
- 复杂片段可拆为多个「子片段」，每个子片段有镜头；**首期只允许一层子片段**。
- 为保持清晰的时序，建议同一片段不要同时混放直属镜头与子片段，镜头归属片段或其最末级子片段。
- 允许子片段尚未细化出镜头，作为上游创作的中间草稿；具体状态和验收留到阶段设计讨论。
- 这样在 30 秒的简单视频不增加多余层级，在较复杂的 2–3 分钟视频又可以组织多个子片段。

### C. 任意深度片段递归

`分集 → 片段 → [任意深度子片段] → 镜头`。可最大化适配复杂电影场景，但引入节点递归、时长继承、跨层排序、分镜归属、移动操作和复杂 UI 展开交互等额外难度。

### 2.1 具体场景压力测试

90 秒独立视频含：

- 开场 15 秒：一个片段，直接放 3 个镜头；
- 冲突 50 秒：一个片段，拆成「误会」「升级」「反击」三个子片段，每个若干镜头；
- 结尾 25 秒：一个片段，直接放 4 个镜头。

选择 B 可以自然覆盖；A 会要求开场和结尾强制增一层子片段；C 则允许更多层，但暂时看不到必须支持无上限递归的理由。

**本轮唯一问题**：是否同意 B「片段下可直接放镜头，也可以选择一层子片段；同一片段不混放直属镜头与子片段」？

### 2.2 尚未解决，后续单独提问

- 「片段」与「场景 Scene」是否需要区分？片段是叙事段落、时序片段，还是物理地点场景？
- 「分镜」是每条镜头的文字规划、关键帧资产，还是两者并列？
- 是否需要在 UI 与数据中将镜头顺序、时长、版本、资产引用做成独立实体？
- 跨分集复用片段或镜头如何处理？
- 剧本场次与导演片段/镜头如何保持稳定映射？

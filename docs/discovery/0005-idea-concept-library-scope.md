# 第六轮 Grill：创意点子与创意方向的归属范围

> 日期：2026-10-30
> 状态：第六轮已定稿，选择简化的方案 A（项目独立 + 复制内容）
> 依据：[CONTEXT.md](../../CONTEXT.md)、[ADR-0001](../adr/0001-idea-to-work-derivation.md)、[ADR-0005](../adr/0005-independent-concepts-before-episode.md)
> 规范：[grill-with-docs](../process/grill-with-docs/SKILL.md)

## 已确认的前置事实

- 一条点子可以派生多集独立短视频，每集拥有一个主创意来源。
- 从点子发散出来的候选创意方向是独立、可修改、可筛选、可保存的内容。
- 用户选择某个方向并决定开始开发时才创建分集，未选方向继续保存在创意储备中。
- 产品的内容管理以项目为中心，但点子及方向是否具有跨项目复用空间尚未决定。
- 此轮仅讨论**创意点子和方向的归属范围**，不涉及角色、场景或媒资的资产共享机制，也不确定 MD/JSON/SQLite 存储位置。

## 场景：一条灵感跨两个项目复用

项目 A《拟人狗狗短片集》已有点子「狗狗能闻出谎言」，及三个候选方向：职场喜剧、法庭悬疑、科幻寓言。

半年后新建项目 B《未来城市》，希望从项目 A 的「狗狗能闻出谎言」衍生出一个全新的反乌托邦故事；同时项目 A 的原有点子、方向、关联分集不应因项目 B 的改写而被静默覆盖。

## 候选方案

### A. 完全项目私有

点子和方向只能属于单个项目；其他项目使用时由用户手动复制文本重新创作。

优点：V1 领域、权限和项目导入/导出最简单。
代价：跨项目搜索、去重和来源回溯较弱，同一创意在多个项目反复出现。

### B. 完全全局创意库

所有点子与方向统一存在全局创意池；项目通过关联关系“借用”它们，分集仍然归属项目。

优点：搜索、复用、统一去重和共享容易。
代价：项目数据包不再独立，用户可能难以区分某项创意修改是否影响其他项目；以后多用户或远端部署的权限划分更复杂。

### C. 以项目为主，明确共享/导入创意（推荐）

每个项目有自己的点子池和候选方向，能够独立管理、导出、备份和恢复；必要时可将点子或创意方向**显式**发布到共享创意库，或从库中导入/复用到另一个项目。

**建议采用“导入时独立副本 + 来源关系”作为默认交互语义**：项目 B 后续改写不会悄悄覆盖项目 A，仍能回溯原始点子。跨项目实时双向同步可以作为未来单独决策，不在本轮自动引入。

优点：满足用户强调的「首先是项目级」与项目批量管理，同时保留长期创意库复用的机会。
代价：需定义明确的分享/导入动作以及来源链，未来还要处理重复创意、归属与权限。

## 原有推荐（已被用户否决）

推荐 C：项目级是内容真实性和创作工作台的主要边界；跨项目复用是**用户主动操作**，而不是所有项目自动共享同一份可变对象。这样后续 Agent Handoff 能优先限定当前项目内容，不会把其他项目的草稿混入当前分集。

**重要未决项**：
- 是否 V1 就完整实现共享库，还是先定义概念、后续渐进交付；
- 导入的是创意点子、创意方向，还是两者一起；
- 跨项目来源关系如何存储、共享/导入后的版本和授权如何管理；
- 同一方向可否创建多集、分集是否允许跳过方向直接建立；
- 点子如何从 Agent 自由交流或外部资源进入项目。

## 第六轮唯一问题

**用户已回答：选择方案 A，并增加简单的“复制创意内容”按钮。**

### 第六轮正式结论（2026-10-30）

- **项目独立**：创意点子与方向只属于一个项目，项目间不共享数据实体。
- **跨项目复用**：在当前项目的创意卡上点击「复制内容」，将文本粘贴给另一项目的 Agent 重新发散即可。复制不等于系统级导入，也不建立跨项目引用关系。
- **明确不做**：全局创意库、显式共享/发布流程、跨项目同步、来源跟踪、跨项目库搜索或复杂资产复用协议。过去关于「导入时独立副本 + 来源关系」的推荐**被否决**，不得作为实现要求。
- **原因**：上述复杂机制对当前的项目内创作、管理与回溯没有明显收益；文本复制已经满足复用需求。
- **落档**：[CONTEXT.md](../../CONTEXT.md)、[ADR-0006](../adr/0006-project-local-idea-pools.md)。

**后续讨论**：转向更重要的阶段产物修改、版本和定稿行为，而不继续扩展跨项目复用模型。

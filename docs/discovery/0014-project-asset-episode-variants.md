# 项目基础资产与分集变体 — 方案 B 确认

> 日期：2026-10-30
> 状态：已确认方案 B
> 依据：[ADR-0015](../adr/0015-project-assets-with-episode-variants.md)、[创作资产模型](../spec/creative-asset-model-and-use.md)

## 用户确认

用户明确选择方案 B：项目级资产负责统一的角色身份、基础外观和场景设定，同一项目中的不同分集可为该基础资产建立自己的造型、服装、状态变体，且不直接改写项目基础设定。

用户追问：「你的意思是根据项目级维护不同图片资产，然后不同分集片段，指定不同图片路径名称这样吗？」

## 产品层解释

可以理解为在项目资产库维护角色/场景的基础图片，分集、片段或镜头选择需要使用的图片和造型。例如同一个角色有统一面部特写和正侧面参考，而 EP01 使用西装造型、EP02 使用未来制服。两集不需要复制整个角色身份。

但「图片路径/图片名称」只是媒体文件定位信息，不应成为业务上的角色身份或引用主键。建议由系统记录稳定的资产 ID、资产版本、分集变体 ID 及图片媒体 ID；实际路径由 Python 业务服务解析。Vue 与 Electron UI 通过资产卡片、变体选择器和图片预览操作，用户不必手工填写文件路径。文件上传、图片角色分类和业务 ID 字段均属于后续实现细节。

## 已确认与未确认的边界

- **已确认**：项目基础资产可在同项目分集间复用；分集有明确的独立造型、服装或状态变体，不直接修改基础定义。
- **已确认**：资产可以在 A3–B4 各阶段建立与完善；B2 是独立制作拆解正式阶段。
- **推荐但未定稿**：镜头具体选择参考图时的优先级、图片分组命名、变体的完整覆盖范围、媒体目录结构、图片上传和引用 API。
- **不涉及**：跨项目共享素材库、外部知识库、实际图片或视频生成 API。

下一步转向 Agent/Skill 的总体编排及这些结构化资产如何按需传递给 Agent，不再针对普通文件名与路径细节逐项 Grill。

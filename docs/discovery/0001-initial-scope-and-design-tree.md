# CinePilot Studio — 需求基线与架构讨论树（第 1 轮）

> 日期：2026-10-30
> 状态：需求基线 + 前十轮决定已确认；其余架构提案仍待讨论（**提案未等同于决策**）
> 工作方式：遵循 [grill-with-docs](../process/grill-with-docs/SKILL.md)，逐个问题讨论、验证、定稿；术语经确认后更新 CONTEXT.md，只有真正满足条件的架构决策才建立 ADR。
> 来源：用户本轮需求及此前关于独立短视频、创意编剧与影视制作流水线的讨论。

## 1. 产品目标（用户已经明确）

CinePilot Studio 是一个将创意编剧与影视制作规划纳入同一项目的 Agent-first 创作及资产管理系统。

- **创作主体**：用户与 Agent 通过对话、多轮调整、审查后定稿；Skill 是 Agent 的专业创作能力，不是自动替代用户确认的流程。
- **管理主体**：系统界面负责组织、浏览、对照、检索、编辑、版本追溯与定稿产物的持久化管理；不再把一次 CLI 对话产生的文件当成唯一可用入口。
- **系统组 A：创意编剧**：①点子发现；②创意发散与筛选；③故事深化与结构设计；④文学剧本编写与审查。
- **系统组 B：影视制作**：⑤导演与视听设计；⑥影视制作规划，包括场景、角色、分镜、镜头动作、提示词等。
- **首期止点**：止于可检查、可修改、可定稿的 AI 影视生成准备产物，**不接实际视频生成**。
- **后续扩展**：预留 ComfyUI、RunningHub、即梦/Seedance 等视频生成适配器，但不让平台特性污染上游内容模型。
- **内容目标**：支持一条视频一个独立剧本；不强制连续短剧叙事；同时需要项目—分集—片段—子片段—分镜的内容组织与回溯。
- **批量准备**：一个项目可以先完成很多条内容的全阶段规划，再统一开展视频生成。
- **持久化倾向**：采用 Markdown + JSON + SQLite 的组合，分别兼顾可读性、结构化与查询管理。
- **跨阶段交接**：长链路 Agent 创作必须保证每阶段读到**被批准且准确**的上游状态及版本，不能靠无限聊天上下文记忆。
- **界面可操作**：所有阶段产物在 UI 中可浏览、审阅、编辑、反馈给 Agent 继续优化，并能追溯定稿前后的历史。

## 2. 待验证的整体形状（不是最终决定）

```text
CinePilot Studio（单一产品）
├── 创意编剧域：点子池 → 创意提案 → 故事大纲/节拍 → 剧本
├── 影视制作域：导演方案 → 段落/镜头规划 → 资产引用 → 生成提示词包
├── 共享能力
│   ├── 项目与内容单元、层级关系、创作素材目录
│   ├── Agent 会话、Skill 注册/选择、任务路由和分阶段交接
│   ├── 版本快照、定稿状态、审查结果、依赖失效提示
│   ├── 文档、结构化内容、关系索引与搜索
│   └── Web 编辑/预览/对照/追溯/人工审批
└── 未来视频执行域（本期不实现）：供应商适配、任务队列、产物回填
```

**初步建议**：两个“系统组”是明确业务边界、共用一个项目空间和基础设施，不一定意味着两个独立部署的应用。正式边界待讨论。

## 3. 数据层次：先区分四类不同的树/图

### 3.1 内容容器层次（待定细节）

**已确认**：`项目 Project → 分集 Episode（即独立作品；一集对应一条独立短视频）`。不引入 `作品 → 分集` 的双层容器，也不强制剧情连续。

**第三轮已确认**：分集 → 片段 → 镜头，或分集 → 片段 → 子片段 → 镜头；子片段可选且最多一层，同一片段不混放直属镜头和子片段，镜头归属唯一最末级单元。见 [ADR-0003](../adr/0003-optional-single-level-subsegments.md)。

**第四轮已确认**：剧本场次与导演片段独立管理，一个剧本场次可拆分为多个导演片段，每个导演片段只关联一个来源剧本场次，参见 [ADR-0004](../adr/0004-screenplay-scene-to-director-segment.md)。

**有待讨论**：草稿阶段的来源约束、镜头详细字段、时长、顺序、稳定 ID 的实现与版本感知。不要先把目录名称等同于数据库层级模型。

### 3.2 创意派生关系（第一轮已经确认）

**已确认方案 B**：`创意点子 Idea 1 → 0..N 独立作品 Work`，每个独立作品**有且只有一个主创意来源**；作品各自维护自己的后续剧本与影视制作产物。参见 [领域词汇表](../../CONTEXT.md) 和 [ADR-0001](../adr/0001-idea-to-work-derivation.md)。

**第二轮补充确认**：`独立作品 Work = 分集 Episode`，每集对应一条独立完整短视频，参见 [ADR-0002](../adr/0002-episode-is-independent-work.md)。

**第五轮已确认**：创意方向 Concept 是可独立保存、筛选、修改和留存的候选故事方案；用户选中方向并决定推进独立视频开发时才创建分集，未选方向保存在创意池。参见 [ADR-0005](../adr/0005-independent-concepts-before-episode.md)。**仍待讨论**：方向与分集的复用基数、是否允许辅助参考多个点子，以及故事方案 Treatment 的身份与版本。

**第六轮已确认**：创意点子、创意方向严格归属单个项目，复用只复制文本并给其他项目 Agent 作为新输入，不建立共享库或跨项目关联。参见 [ADR-0006](../adr/0006-project-local-idea-pools.md)。

### 3.3 阶段产物与依赖图（第七轮部分已确认）

**第七轮已确认**：每一阶段的已定稿产物不得被 UI 或 Agent 后续修改直接覆盖；修改产生新草稿，用户再次确认形成新的定稿，旧版本及其已有下游成果继续保留，见 [ADR-0007](../adr/0007-approved-artifact-revision-policy.md)。

**第八轮已确认**：上游定稿更新后，系统依据明确的版本依赖标记相关下游为待复核，不自动重做；用户决定是否继续沿用或委托 Agent 修订，见 [ADR-0008](../adr/0008-review-dependent-artifacts-without-auto-regeneration.md)。

**第九轮已确认**：同一分集的正式下游阶段必须等待上游所需产物定稿，且各分集可独立或批量推进；前置的点子/方向仍按分集创建前的创意流程管理。参见 [ADR-0009](../adr/0009-approved-upstream-stage-gates.md)。

其他实现细节仍待决定。每一阶段产物有固定身份、具体版本、输入来源、上游版本引用、审查状态和下游影响范围。
例如：剧本 v4 定稿 → 导演方案 v2 → 分镜 v3 → 提示词 v5。若剧本被修订为 v5，不立即删除下游；标出需评估/可能失效的下游版本。

### 3.4 资产引用图（待定）

角色与角色设定、场景与场景设定、世界观、服装道具、风格规范、参考图、声画参考、镜头提示词是**可被多个内容单元引用的资产**；不能简单复制多份后失去一致性。
资产需要区分项目级共享定义、分集级选择/覆写、片段级使用、镜头级实际引用及版本钉选。

## 4. 持久化三件套的建议职责（待决）

| 载体 | 候选职责 | 风险点 |
|---|---|---|
| Markdown | 剧情文本、剧本、导演意图、审核意见和人类可读内容 | 结构字段与 JSON 双向修改的冲突 |
| JSON | 具 Schema 的内容实体、场景/片段/镜头、prompt 与 handoff 清单 | Schema 演化、版本迁移、嵌套增量更新 |
| SQLite | 项目目录索引、稳定 ID、实体关系、版本/审批/操作索引、任务/会话查询 | 多进程一致性、数据库与文件提交的原子性 |

**重要原则候选**：同一字段必须明确唯一写入权威；不能让 Markdown、JSON、SQLite 三份都各自声称是唯一真实来源。由受控写入服务提交产物，Agent 和 Web UI 经过相同校验/版本控制。

## 5. Agent / Skill / handoff 机制建议（待决）

- **Agent**：负责创意内容、故事质量、剧作、导演规划、提示词等需要推理的工作。
- **代码编排层**：负责阶段进入条件、输入版本、产物校验、状态转换、保存、审批门禁、失效检测；不能仅让一个大路由 Skill 靠提示词“记住”规则。
- **Skill Router（候选）**：识别用户在当前项目/阶段的创作意图、选择允许调用的专业 Skill；必须受当前阶段和权限约束。
- **专业 Skill（候选）**：
  - Idea Generator / Creative Director：点子发现与创新发散。
  - Short Film Development：故事冲突、节拍和完整性。
  - Comedy Skill：特定题材的可选插件，不应强制所有项目走喜剧模板。
  - Screenwriter：文学剧本。
  - Director / Storyboard / Prompt：下游导演、分镜与生成准备。
- **第十轮已确认**：采用精简、版本明确、可按需补充原文的正式 Handoff，避免默认传入全部聊天和大量文档；任务目标、上游已定稿版本、重要确认约束与产物要求必须可追溯，见 [ADR-0010](../adr/0010-compact-versioned-agent-handoff.md)。
- **工程候选（未批准）**：将大内容保留于 MD/JSON/数据库，交接中只保留少量关键事实、版本锚点与查询依据；经受控接口按需取文档，可在 SQLite 上建立全文索引，但暂不要求部署知识库。参见 [第十一轮讨论](./0010-controlled-on-demand-retrieval.md)。
- **反馈闭环**：Agent 草稿 → 系统校验与预览 → 人工批注/编辑 → Agent 定点改稿 → 用户定稿 → 固化版本与下游交接。
- **记忆分层**：长期项目世界观/约束、单作品阶段事实、当前任务精简上下文、完整可追溯聊天记录。handoff 不应依赖聊天窗口无限延长。
- **待验证**：首期 Agent 执行方式（Codex CLI / Claude CLI / SDK / API）、Skill 装载/隔离、权限与文件访问边界。

## 6. 前端建议的核心工作台（待决）

1. 项目首页：作品单元列表、创作进度、待确认/待重审、资产概览。
2. 创意池：点子卡、派生方向、筛选/归档、引用到作品单元。
3. 作品工作台：阶段时间线 + 对话侧栏 + 当前产物编辑器/预览区。
4. 故事/剧本：剧情卡、节拍、场景、对白、历史版本差异。
5. 导演/镜头：片段树、镜头表、镜头时长顺序、角色场景/道具引用、提示词。
6. 资产库：共享规范与角色/场景实体、使用关系及版本。
7. 审批与回溯：变更源、差异、影响范围、重新生成建议、恢复与审计。

本期不构建生成队列、供应商接入、生成结果自动回填；界面仍可以有“待制作包导出/批量准备就绪”状态。

## 7. 讨论顺序（每次一问，确认后记录）

1. **内容身份与创意派生基数**：点子、创意方向、独立作品/分集是否一对多，能否复用和合并。
2. **单元结构与层次**：项目、分集、片段、子片段、镜头的语义、粒度、可选性。
3. **两业务域的边界、产物清单与通过标准**：哪些产物必须有，哪些可选。
4. **共享角色/场景/风格资产及继承/覆写**：跨分集引用，漂移控制。
5. **版本、定稿、返工与依赖失效**：不同阶段不同状态与恢复策略。
6. **Agent 对话与系统写入权**：CLI/Web、结构化工具、权限、人工作业。
7. **Skill 编排与路由**：意图、角色、专业 Skill 组合、代码门禁。
8. **handoff / 长上下文记忆**：快照、摘要、溯源、冲突。
9. **MD/JSON/SQLite 事实来源与一致性**：事务、索引重建、同步。
10. **UI 信息架构与编辑回路**：跨阶段呈现、差异、批量化。
11. **实现技术与部署形态**：前后端、服务、SQLite 并发、桌面/远端。
12. **V1 边界与验收**：哪些必须交付、未来视频接口如何预留。

每轮将明确「已确认 / 候选方案 / 待答」，不能因为写入文档就认定架构已通过。

## 8. 第一轮结论（2026-10-30，已确认）

**用户选择 B：一条点子可以派生多个独立作品，每个作品有一个主创意来源。**

- **保留**：同一灵感可派生多个题材、故事和剧本各自独立的作品。
- **保留**：每个作品恰有一个主创意点子，便于溯源与展示。
- **没有提前决定**：辅助点子引用、候选创意方向身份、多集与作品的对应、跨作品融合机制。
- **已归档**：[CONTEXT.md](../../CONTEXT.md)（定义与例子）；[ADR-0001](../adr/0001-idea-to-work-derivation.md)（选择理由与替代方案）。

## 9. 第二轮结论（2026-10-30，已确认）：独立作品与分集是同一个概念

项目要管理「分集」，而首轮已确定「独立作品」身份。必须先明确两者关系，后续才能设计片段、子片段、镜头的归属层级。

- **A. 同一概念（推荐）**：每个独立作品就是一条可独立成片的短视频，在项目管理界面可称「分集」；并不强制故事连续。一个项目可有多部独立作品。
- **B. 两级容器**：项目 → 独立作品 → 多个分集，一部作品本身可以拆成多条发布视频；会额外引入剧本与视频交付单元的分界。
- **C. 混合层级**：项目下同时允许独立视频和连续多集系列，提供可选的「系列」容器；更通用但复杂度更高。

**边界例子**：一个项目内做 20 条各自完整的拟人化狗狗短视频，每条 90 秒、独立标题与剧本。推荐 A：每条都是一个独立作品 / 分集，项目并不自动变成连续剧。

**已确认方案 A**：`项目 → 分集（独立作品）`，每集独立剧本，可选剧情连续性，不新增 `作品` 这一中间层级。正式领域词汇见 [CONTEXT.md](../../CONTEXT.md)，重要取舍见 [ADR-0002](../adr/0002-episode-is-independent-work.md)。

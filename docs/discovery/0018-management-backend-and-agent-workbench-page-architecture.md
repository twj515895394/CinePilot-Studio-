## 用户反馈与目标

上一轮的 [Python API 与 Vue/Electron 工作台设计](../spec/python-api-and-vue-electron-workbench.md) 重点描述 Agent 对话创作工作台，用户指出这并不等同于完整后台管理系统；同时要求把对话过程中当前阶段、产物查看和展示等细节一起考虑。用户明确本轮先设计“页面该有的东西”，视觉样式和 UI/UX 留到后续实施阶段。

## 本轮设计结论

将同一个产品界面分为两个职责清晰、数据与业务服务统一的区域：

1. **项目管理后台**：独立管理项目、创意、分集、阶段、产物、版本、审查、资产/媒体、Skills、Agent Runs、活动记录和导入导出。用户不打开 Agent 对话也能阅读、编辑、比较和追溯已保存的创作成果。
2. **Agent 创作工作台**：在明确的项目/创意/分集/阶段上下文中与 Agent 对话，实时查看当前阶段产物目录、正文和结构化内容，选中 Scene/Segment/Shot 做局部编辑/定点修改，查看本次 Handoff 来源，检查草稿保存结果并进行阶段整体审查。

**两个区域不维护两份数据**：统一使用 SQLite + Markdown/JSON/媒体文件和 Python 业务服务。后台手动编辑与 Agent 修改都通过同一个草稿/Revision 服务，阶段定稿仍以用户显式批准为准。

## 已有决策保持不变

- Vue + Python + Electron；
- 全系统共用一个 SQLite，项目文件各自独立；
- 项目 Agent 工作区隔离，Agent 不能访问其他项目；
- A1/A2 为项目级创意池，选中 Concept 后才创建 Episode；
- A3–B4 分集阶段；Scene 与 Segment 分离；Segment 最多一层 Subsegment；
- 项目基础资产可在同项目多集复用，每集可有独立变体；
- 正式审批以阶段为单位，Scene/Segment/Shot 可局部编辑，不逐镜头审批；
- 定稿不可覆盖；上游变化标记下游待复核，不自动重做；
- V1 不接视频生成。

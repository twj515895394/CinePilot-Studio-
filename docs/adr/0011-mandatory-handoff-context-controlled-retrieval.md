# 阶段启动由系统提供必需事实，详细资料由 Agent 受控按需读取

**状态：accepted**  
**日期：2026-10-30**

CinePilot Studio 的正式 Handoff 不应只有几个索引 ID、让 Agent 自己摸索全部必需资料，也不应为减少查询而整包加载大量可能有关的文档。系统应先根据正式阶段的任务与版本约束，提供少量**不可遗漏的任务目标、强制创作约束和确定的上游已定稿版本依据**；Agent 通过系统控制的查询接口，根据项目、分集、对象及版本读取所需详细原文。这样兼顾可靠的阶段上下文和较小的初始 Token 负担，避免丢失约束、读错版本与多次无意义查询。

**考虑的选项**：完全交给 Agent 检索会漏读强约束、增加重复查询延迟；一次预加载所有可能相关文档会再次造成上下文膨胀。用户明确选择系统预置必要上下文、Agent 查询细节的组合。

**边界**：不因此决定知识库或向量数据库的部署，也不提前确定查询工具 API、检索索引、Token 预算、预取粒度与 SQLite/Markdown/JSON 的唯一数据权威；Web 管理后台对创意、剧本、分镜等定稿产物的展示与编辑仍需独立设计。

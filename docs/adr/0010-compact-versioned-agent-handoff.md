# 正式 Agent Handoff 采用精简、版本明确且可按需展开的交接资料

**状态：accepted**  
**日期：2026-10-30**

CinePilot Studio 的正式阶段交接不默认传入完整聊天历史，也不能仅依赖上一阶段的一份最新文档。系统应依据同一分集的已定稿产物版本、有效创作约束、已确认关键决策以及目标阶段的任务与产物要求，形成精简、可追溯的 Handoff；需要更详细上下文时可按明确来源补充读取原文。选择此方案是为避免长时间 Agent 对话和大批创作文档造成 Token 臃肿、执行变慢与旧草稿误用，并保证阶段复盘及跨 Skill 协作的可靠性。

**考虑的选项**：全量输入聊天历史虽然保留大量细节，但混入被否决的草稿、消耗 Token；只传前一个已定稿文档则可能遗漏角色、风格与项目级约束。精简、版本锚定的交接资料在信息充分性与成本之间取得平衡。

**尚未决定**：按需检索究竟由 Agent 发起、由系统预取还是混合；SQLite 与 Markdown/JSON 的权威数据划分、是否需要全文索引或向量知识库；查询工具接口、检索结果预算与版本过滤的具体机制。用户提出“数据库/知识库保存大内容，Handoff 只留关键索引”是值得研究的工程方向，但**尚不视为已批准引入知识库或某项检索技术**。

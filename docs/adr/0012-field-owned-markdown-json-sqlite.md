# Markdown、JSON 与 SQLite 按领域字段拥有唯一权威

**状态：accepted**
**日期：2026-10-30**

CinePilot Studio 选择三类载体分工：Markdown 保存文学剧本、故事叙述与导演阐述等创作正文；JSON 保存创意卡、场次、片段、镜头、提示词等结构化产物；SQLite 保存项目和分集身份、内容引用、版本、审批状态和查询索引。每个字段只有一处可写入的权威来源。Web UI 和 Agent 均通过统一业务服务查询、提交、校验、定稿，不允许绕过服务分别修改文件和数据库。后台仍能按项目、分集和版本完整浏览创意、剧本和分镜等产物。

**备选方案**：全部由 SQLite 负责内容虽便于单库事务，但不契合文件型创作；全部由文件负责且 SQLite 仅索引则使关系、版本及审批状态维护复杂。按字段分工适合现有创作和展示需求。

**未决定**：具体字段定义、文件和数据库间的保存一致性及故障恢复、Schema、接口与编辑器。数据库事务不自动包含外部文件操作；这需要下一轮专门确定。

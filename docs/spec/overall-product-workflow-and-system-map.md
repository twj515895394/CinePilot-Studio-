## 1. 产品定位

CinePilot Studio 是一个 **Agent-first 的短视频创意、剧本与影视制作规划工作台**。它把此前分散在 Codex/其他 Agent 对话和 Skill 文件中的创作过程，转化为可持久化、可浏览、可编辑、可定稿、可追溯的完整项目。

产品由两个业务系统组成，但建议首期作为**一个产品、一个项目空间、一个管理后台、共享一套数据与 Agent 编排基础设施**：

1. **创意编剧系统**：从灵感和创意储备出发，完成方向筛选、故事深化和文学剧本。
2. **影视制作系统**：从已定稿剧本出发，完成导演设计、制作拆解、分镜镜头规划和视频生成提示词准备。

Agent 是主要创作者，Skill 提供专业能力；用户负责讨论、选择、审阅、修改和定稿；系统负责阶段管理、数据保存、版本关系、查询、校验和可视化工作台。

### 已确认的技术基线（用户明确要求）

- **Vue**：Web 创作与管理前端；Electron 桌面端复用这套界面。
- **Python**：后端业务服务、Agent/Skill 编排、Handoff、数据访问与版本控制。
- **Electron**：必须支持桌面应用交付，而不仅是浏览器版；保留与 Web 端共享界面和业务接口的原则。
- **SQLite + Markdown + JSON**：已确认的分字段权威存储方式，业务服务是 UI 和 Agent 的统一读写入口。

**推荐的逻辑结构（实现细节未定稿）：**

~~~text
Web 浏览器 ── Vue SPA ─────────┐
                              ├── Python 统一业务服务 / Agent Orchestrator
Electron 桌面 ── 同一 Vue UI ──┘       ├── Markdown / JSON 文件产物
                                      └── SQLite 状态 / 版本 / 关系
~~~

Electron 主进程如何启动和停止 Python 后端、本地运行还是连接远程 Python 服务、开发与发布环境打包方式、Web 认证及 API 技术选型均留待技术实现设计，不等于确认 FastAPI、Pinia 或任何具体组件库。


### V1 目标

完整做到从「一个点子」到「一套可交付给视频生成工具的制作准备包」，包括创意、故事、剧本、导演方案、角色/场景等视觉设定、剧本场次与导演片段映射、片段/子片段/镜头/分镜与提示词，以及项目/分集/素材/版本/审批/依赖关系管理。

**V1 不执行实际视频生成**，不接 ComfyUI、RunningHub、即梦/Seedance 等生成接口；数据结构为未来接入保留清晰边界。

## 2. 产品核心原则

1. **Agent 创作，系统管理**：Agent 不负责靠聊天记录维持整个项目；系统也不替代创作判断。
2. **产物优先于聊天**：聊天过程可追溯，但真正可交付、可复用、可进入下一阶段的是被保存的阶段产物。
3. **阶段明确，分集独立**：同一分集正式进入下游阶段前，所需上游产物必须定稿；不同分集可以独立或批量推进。
4. **定稿不可覆盖**：修改定稿先产生新草稿，用户确认后形成新定稿；旧版本和原下游成果保留。
5. **精简 Handoff，按需取文档**：系统预置任务目标、强制约束和准确版本锚点；Agent 通过受控接口按需读取详细内容。
6. **唯一事实来源**：Markdown 管创作正文，JSON 管结构化产物，SQLite 管对象关系、版本与审批；同一字段只有一个权威写入来源。
7. **统一业务服务**：Web UI 与 Agent 使用同一服务读写和校验数据，不允许两套独立写入逻辑。
8. **批量规划、独立定稿**：可以批量生成/推进多集，但每集仍保有独立内容、版本和用户定稿。
9. **先做可用闭环，不预建重型基础设施**：首期不强制部署独立知识库、向量数据库或视频生成服务。

## 3. 端到端创作流程

### 3.1 两大系统与建议阶段图

~~~text
项目 Project
│
├── A. 创意编剧系统
│   ├── A1 点子发现 / Idea Discovery
│   │      ↓ 保存为项目级创意点子
│   ├── A2 创意发散与筛选 / Concept Exploration
│   │      ↓ 一个点子可产生多个独立创意方向
│   │      ↓ 用户选中方向并决定开发，才创建分集
│   ├── A3 故事深化与结构设计 / Story Development
│   │      ↓ 故事核心、人物目标、冲突、节拍、结局、故事大纲
│   └── A4 文学剧本 / Screenplay
│          ↓ 完整剧本、场次、动作与对白
│
├── B. 影视制作系统
│   ├── B1 导演阐述与视听设计 / Directorial Vision
│   │      ↓ 导演意图、风格、表演、节奏、视听语言
│   ├── B2 制作拆解 / Production Breakdown（独立阶段，已确认）
│   │      ↓ 剧本场次拆为导演片段，可选子片段
│   │      ↓ 本集角色/场景/服装/道具需求与引用核对
│   ├── B3 分镜与镜头规划 / Storyboard & Shot Planning
│   │      ↓ 镜头顺序、景别、机位、运镜、动作、时长、分镜参考
│   └── B4 视频生成提示词 / Video Prompt Package
│          ↓ 镜头级提示词、角色/风格一致性约束、整集制作包
│
└── V1 交付：可审阅、可修改、可导出的影视生成准备包
    V2+：视频生成适配器与任务执行（本期不实现）
~~~

**说明：** A1/A2 是项目级、分集创建前的创意管理；A3/A4 与 B1–B4 为分集级正式创作阶段。**B2 是独立制作拆解阶段，资产管理贯穿 A3–B4**，这一边界已确认；其余各阶段详细产物字段与验收标准仍是设计草案。

### 3.2 各阶段的目标与候选产物

| 阶段 | 作用域 | 核心目标 | 候选主要产物 |
|---|---|---|---|
| A1 点子发现 | 项目 | 找到值得开发的短视频创意种子 | 点子卡：一句话钩子、核心冲突/反差、题材、情绪、受众、潜在看点 |
| A2 创意发散与筛选 | 项目 | 围绕点子生成多条差异明显的创意方向并比较 | 多个独立方向卡、差异说明、优劣/风险、推荐与用户选择记录 |
| A3 故事深化与结构设计 | 分集 | 把选定方向发展为可成立的完整短故事 | 故事梗概、人物目标与关系、冲突升级、节拍/结构、转折、结局、故事大纲 |
| A4 文学剧本 | 分集 | 将故事结构转成可拍摄/可视化的完整剧本 | 文学剧本 Markdown、场次结构 JSON、动作与对白、场次 ID |
| B1 导演阐述与视听设计 | 分集 | 定义作品如何被观众看见和感受到 | 导演阐述、视觉/声音基调、节奏、表演方向、摄影与镜头语言原则 |
| B2 制作拆解（已确认的独立阶段） | 分集（引用项目资产） | 把剧本转换为导演制作片段并核对所需视觉资产 | 场次→导演片段映射；片段/子片段结构；本集素材需求和资产引用 |
| B3 分镜与镜头规划 | 分集 | 将导演片段转化为有序、可执行的镜头设计 | 镜头表、镜头动作、景别/角度/运动、时长、构图、转场、分镜图/关键帧引用 |
| B4 视频生成提示词 | 分集/镜头 | 把已确认的镜头方案转化为目标生成模型可使用的提示词包 | 镜头级 prompt、负面约束、角色/场景引用、连续性约束、整集生成准备包 |

以上是产品层的产物类别建议，不是最终 JSON 字段或 Markdown 模板。每阶段详细的必需/可选产物、审核标准、输入版本与 Handoff 合同后续统一整理。

### 3.3 创意到分集的生命周期

~~~text
项目
 └── 创意池
      ├── 点子 I-001
      │    ├── 方向 C-001（保留/待选）
      │    ├── 方向 C-002（选中） ──→ 创建分集 EP-001
      │    └── 方向 C-003（归档）
      └── 点子 I-002
           ├── 方向 C-004
           └── 方向 C-005（选中） ──→ 创建分集 EP-002
~~~

已确认规则：

- 一条点子可以派生多个候选方向。
- 点子和方向属于单个项目，不存在全局共享创意库。
- 创意方向独立保存、筛选、修改和归档。
- 用户选择方向并明确进入视频开发时才创建分集。
- 每个分集有且只有一个主创意点子；分集能追溯所选方向。
- 一个分集就是一条独立短视频，不另设「作品」中间层。

## 4. 分集内部内容结构

### 4.1 文学剧本结构与导演制作结构分离

文学剧本和导演片段是不同的内容对象，不能强制一场剧本戏等于一个导演片段。

~~~text
EP-001
├── 剧本
│   ├── S01 场次
│   ├── S02 场次
│   └── S03 场次
│
└── 影视制作规划
    ├── P01 导演片段 ← 来源场次 S01
    │   ├── SH001 镜头
    │   └── SH002 镜头
    ├── P02 导演片段 ← 来源场次 S03
    │   ├── 子片段 P02-A
    │   │   ├── SH003 镜头
    │   │   └── SH004 镜头
    │   └── 子片段 P02-B
    │       └── SH005 镜头
    └── P03 导演片段 ← 来源场次 S03
        └── SH006 镜头
~~~

已确认规则：

- 一个剧本场次可拆成多个导演片段。
- 每个导演片段只对应一个明确来源剧本场次。
- 片段可直接包含镜头，也可包含最多一层子片段再组织镜头。
- 同一片段不混放直属镜头和子片段；镜头只归属唯一的最末级单元。
- 剧本场次不是地点资产；同一地点可在多个剧本场次出现。

### 4.2 角色、场景和其他制作资产

**已确认**：资产管理是 A3–B4 的横向能力，而非必须在 B2 一次性创建完毕的线性阶段；B2 则独立负责制作拆解和资产需求核对。参见 [ADR-0014](../adr/0014-production-breakdown-with-cross-stage-assets.md)。

候选资产类别：

- 角色：身份、外观、年龄感、体型、服装、表情、动作特征、参考图。
- 场景/地点：空间结构、布局、材质、光线、时间/天气、参考图。
- 服装与道具：归属角色、外观、状态、剧情用途、连续性要求。
- 视觉风格：画风、色彩、光影、质感、构图与镜头语言基准。
- 声音资产：角色声音设定、环境声/音乐方向（首期可先保存文字设定）。

建议的使用层级：

- **项目级**：可供本项目多集引用的基础角色、世界观、视觉规范和常用场景。
- **分集级**：本集选用的资产版本、临时角色/场景及必要覆写。
- **片段/子片段级**：当前段落实际出现的角色、场景、服装和道具。
- **镜头级**：镜头实际引用的资产版本、状态和提示词约束。

**项目级基础资产可在同一项目的分集间复用，分集可以建立造型、服装、状态等显式变体，不改变项目基础定义——已确认方案 B**，见 [ADR-0015](../adr/0015-project-assets-with-episode-variants.md)。片段/镜头的具体选择与覆盖优先级、文件路径和版本锁定实现仍待细化，详见 [创作资产模型](./creative-asset-model-and-use.md)。不因此增加跨项目资产共享。

## 5. Agent、Skill 与系统编排

**Agent/Skill 详细协作设计：** [Agent / Skill 协作与运行架构](./agent-skill-orchestration-and-runtime.md)。涵盖 Router、专业 Skill、任务与会话、精简 Handoff、受控读取角色图片、Agent Runtime Adapter、草稿写回及 Vue/Electron 任务进度。**已确认**：V1 CLI 生态优先、可通过官方 Agent SDK 控制；项目创建即建立独立 Agent 工作区，Skill 从集中目录按项目启用并只读投射，Agent 绝不可以访问其他项目。参见 [ADR-0016](../adr/0016-cli-first-with-official-agent-sdk.md)、[ADR-0017](../adr/0017-project-isolated-agent-workspaces-and-skill-projection.md) 与 [项目隔离工作区详细设计](./project-isolated-agent-workspaces-and-skills.md)。具体供应商、沙箱及 SDK/CLI 版本实现仍未定稿。

### 5.1 责任分工

| 参与者 | 负责什么 | 不负责什么 |
|---|---|---|
| 用户 | 创意方向选择、反馈、编辑、审阅、最终定稿 | 不需要手工管理文件路径或版本 ID |
| Agent | 理解意图、专业创作、根据反馈修改、解释创作选择 | 不自行决定系统阶段状态，不覆盖定稿 |
| 专业 Skill | 提供某个创作领域的方法、检查清单、产物结构和质量标准 | 不承担数据库事务和阶段权限控制 |
| Skill Router | 识别当前任务、选择合适的专业 Skill 或 Skill 组合 | 不单独承担系统级状态门禁 |
| 系统编排服务 | 阶段准入、版本钉选、Handoff 组装、查询工具、产物校验、保存、定稿与依赖标记 | 不替代 Agent 进行创作判断 |
| Web 管理后台 | 展示、编辑、比较、审查、批量管理和追溯产物 | 不直接绕过业务服务写数据库或文件 |

**关键建议：** Skill Router 可以由一个入口 Skill 辅助，但阶段权限、定稿门禁、版本和数据写入必须由系统代码控制，不能只依赖 Prompt 约定。

### 5.2 Skill 能力角色与外部候选

以下是能力角色分类，不代表已安装或已选定具体 Skill；真实候选和阶段绑定以 [Skill Registry 与阶段编排规格](./stage-skill-orchestration-and-registry.md) 为准。

**创意编剧 Skill 组**

- Idea Scout / Idea Generator：点子发现、创意种子生成。
- Creative Divergence / Concept Strategist：从一个点子发展多条差异化方向。
- Story Architect：人物目标、冲突、节拍、转折、结局和故事结构。
- Screenwriter：短视频文学剧本、场次、动作和对白。
- Genre Skills：喜剧、悬疑、科幻、动作、温情等按题材选用的可选能力，不应强制所有作品走同一题材模板。

**影视制作 Skill 组**

- Director：导演阐述、视听风格、表演与节奏。
- Visual Development / Asset Designer：角色、场景、服装、道具和视觉规范。
- Scene Breakdown / Production Planner：剧本场次拆解、导演片段规划、资产使用安排。
- Storyboard & Shot Designer：镜头语言、镜头表、分镜图/关键帧描述。
- Video Prompt Engineer：将镜头和资产约束转换为视频模型提示词。

以上是职责拆分，不意味着 V1 必须安装十几个独立 Skill。可以先用少量高质量 Skill 覆盖多个紧密相关任务，再根据实际质量与维护成本拆分。外部候选未完成 License、质量、Runtime 兼容和阶段合同评估前，不得标记为已启用。

### 5.3 推荐的 Agent 创作闭环

~~~text
用户在项目/分集阶段工作台提出任务
          ↓
系统确定项目、分集、当前阶段与可用定稿版本
          ↓
Router 识别意图，选择专业 Skill
          ↓
系统组装精简 Handoff（任务、强制约束、版本锚点）
          ↓
Agent 通过受控工具按需读取指定原文/结构数据
          ↓
Agent 提交结构化草稿或正文草稿
          ↓
统一业务服务校验、保存并生成预览
          ↓
用户在 UI 查看、编辑、批注或要求 Agent 定点修改
          ↓
用户确认定稿
          ↓
SQLite 记录定稿状态与上游版本依赖，开放下一阶段
~~~

### 5.4 Handoff 的最小组成

正式 Handoff 应是短小、可重建的任务资料，而不是完整聊天记录。建议包含：

- 项目 ID、分集 ID（创意池阶段可没有分集 ID）、目标阶段。
- 当前任务目标与范围。
- 必须遵守的已确认约束摘要。
- 上游已定稿产物 ID 和确切版本。
- 本阶段产物要求与允许修改边界。
- Agent 可使用的受控查询范围。

详细剧本、角色卡、场次、镜头和历史版本通过工具按需读取。完整对话可作为会话记录保存供用户查看，但不默认传给下一阶段。

### 5.5 Agent 接入、模型配置与阶段 Skill 编排

Agent、Model 和 Skill 是三套独立配置：

- **Agent Runtime**：负责实际执行任务；V1 CLI 生态优先，官方 Agent SDK 可用时优先评估。
- **Model**：从所选 Runtime Adapter 动态发现；模型 ID、推理等级和参数不做跨 Agent 硬编码。支持什么就展示什么，不支持则使用 Runtime 默认模型。
- **Skill**：负责专业创作方法；系统级 Registry 管理来源/版本/License，项目按 A1–B4 配置 Stage Skill Profile。

配置解析：
- Agent/Model：任务覆盖 → 分集阶段覆盖 → 项目阶段配置 → 项目默认 → 系统默认；
- Skill：任务 Skill Override → 分集阶段 Skill Override → 项目 Stage Skill Profile → 系统阶段模板。

每个阶段可配置主 Skill、辅助 Skill、条件/题材插件和 Review Skill；一个 Skill 可跨阶段复用，一个阶段可组合多个 Skill。Python Skill Router 在 Run 启动前生成可解释 Skill Plan，按需加载 references，避免每次把所有 Skill 放进上下文。

**第一批八个候选来源**：Story Idea Generator、Short Film Development、Comedy Short Video Skill、Stephen Chow Skill、Creative Director、AI ShortVideo Story Engine、Wind Comic Screenwriter、Storytelling Frameworks。它们的仓库、Skill 路径、License 核验、Commit SHA 和阶段候选映射见 [Skill Registry 与阶段编排规格](./stage-skill-orchestration-and-registry.md)。B1/B2/B4 缺失 Skill 由用户后续补充；不虚构占位外部 Skill。

详细规格：
- [Agent 接入与模型管理](./agent-integration-and-model-management.md)
- [Skill Registry 与阶段 Skill 编排](./stage-skill-orchestration-and-registry.md)

## 7. 管理后台与 Agent 创作工作台的信息架构

产品界面明确分为两个职责不同、数据与服务统一的区域：

1. **项目管理后台**：负责项目、创意、分集、阶段进度、已保存产物、版本、审批、资产、Agent 任务、Skill 和系统设置的浏览与管理。即使不进入 Agent 对话，也必须能够查看、编辑和追溯全部已保存内容。
2. **Agent 创作工作台**：围绕当前项目/创意/分集/阶段开展对话创作；对话期间必须同步提供阶段导航、当前阶段产物目录、正文/结构化内容预览与编辑、局部对象定位、上游来源和版本信息、任务事件、草稿保存及阶段整体审查。

**两者使用同一套 Project/Episode/Artifact/Revision/Asset/AgentRun 数据与 Python 业务服务，不维护两份内容。** 管理后台独立编辑产生的草稿和 Agent 提交的草稿走同一 ArtifactService；Agent 对话中保存的产物自动进入后台产物库。

**完整页面清单、职责、功能区、操作、页面跳转和状态要求**：见 [产品信息架构与页面功能规格](./product-information-architecture-and-page-functions.md)。该文档是页面功能设计的主参考；本节只保留系统级摘要，不重复全部页面细节。

### 7.1 项目管理后台主要页面

- **Dashboard / 项目总览**：项目活动、待审查、待复核、Agent 任务和最近产物。
- **项目列表与项目空间**：新建/打开项目、项目概览、创意池、分集、项目资产、产物库、项目 Skills、活动和项目导出。
- **创意池**：项目级 Idea/Concept 管理、比较、编辑、归档、选中方向并创建 Episode。
- **分集管理**：Episode 列表、单集概览、A3–B4 阶段进度和正式准入状态。
- **创作产物库**：跨阶段浏览所有已保存成果，按类型/分集/阶段/版本查看、编辑、比较和导出；不依赖聊天历史。
- **素材资产库**：角色/场景/服装/道具/风格、媒体多视图、项目基础版本和分集变体、使用关系。
- **审查中心**：待定稿产物、阶段完整性、上游版本来源和下游待复核事项。
- **Agent 任务中心**：跨项目 Run 列表、执行详情、Handoff、Skill、事件、输出和运行状态。
- **系统设置**：Agent Runtime、系统 Skill Registry、数据存储与备份、应用设置。

### 7.2 Agent 创作工作台的必要功能区

- **当前上下文**：项目/Idea/Concept/Episode/Stage、准入状态、当前 Artifact/Scene/Segment/Shot。
- **阶段导航**：创意池 A1/A2 或分集 A3–B4；展示阶段进度和上游定稿门禁。
- **产物目录**：本阶段必需/可选产物、草稿/定稿/历史版本和待复核状态。
- **内容查看/编辑区**：按类型呈现 Markdown 正文、故事结构、场次、片段树、镜头表/卡片、提示词和资产媒体；不能只展示原始 JSON 文件。
- **Agent 对话与任务区**：指定任务范围、流式输出、任务事件、草稿提交结果；聊天与选中产物双向联动。
- **上下文/来源区**：本次 Handoff 的上游 Revision、已确认约束、按需读取的对象摘要。
- **版本与审查区**：草稿差异、结构校验、阶段必需产物完整性、用户显式阶段定稿。

### 7.3 重要内容体验原则

- 管理后台可脱离聊天查看和编辑已保存产物；聊天记录不是创作正文的唯一存储。
- 用户在聊天时选中一个 Scene/Shot，Agent 任务明确绑定该对象；提交草稿后内容区定位并展示修改结果。
- “模型已输出”“草稿已保存”“阶段已定稿”是三个不同状态，不能混淆。
- Scene/Segment/Shot 可局部编辑，但正式审批仍以阶段采用的产物 Revision 集合为单位，不要求逐镜头审批。
- 上游变更后，旧下游仍可见并标记待复核，不自动重做。
- 页面功能与信息架构先确定；视觉样式、组件库、高保真 UIUX 和具体布局在后续设计阶段处理。

## 8. 多分集批量创作与准备

批量能力是产品主路径的一部分，而不是后期附加功能：

- 一个点子可以发散多个方向；用户可批量选中多个方向，分别创建独立分集。
- 项目可先集中完成多集故事和剧本，再进入导演与分镜阶段。
- 可对多集执行相同阶段的批量任务，例如批量启动剧本初稿或提示词检查。
- 批量任务可以共享任务模板和 Skill 配置，但每集输入版本、草稿、审阅和定稿彼此独立。
- 管理后台提供按阶段筛选的列表，例如「剧本待定稿」「可进入导演阶段」「分镜已完成」「提示词包已准备」。
- 最终可以对选定分集批量导出制作准备包。

批量推进不能绕过每集的正式阶段门禁；不同分集状态不要求同步。

## 9. V1 范围与非目标

**V1 已确认平台要求：** Vue Web 前端、Python 后端，并且支持 Electron 桌面端。推荐两端复用业务 UI、共用后端服务与阶段规则，而不是开发两套业务代码；平台运行方式仍待技术设计。

### V1 必须具备

- 项目、创意点子、创意方向和分集管理。
- A1–A4 与 B1–B4 的完整创作流程（阶段合同细节后续确定）。
- Agent 对话入口、Agent Registry/Adapter、Connection Profile、动态模型/参数发现、Agent Model Profile 与 Run 配置快照。
- A1–B4 八个阶段的 Stage Skill Profile、系统 Skill Registry、Skill Router/Skill Plan、项目启用与版本固定；缺失阶段 Skill 可暂为空，用户后续补充。
- Agent 对话入口、专业 Skill 调用、受控读写工具。
- 精简 Handoff、准确版本引用和按需读取。
- Markdown/JSON/SQLite 的权威分工与统一业务服务。
- 草稿、定稿、历史版本、上游依赖和待复核标记。
- Web 后台浏览、编辑、审查、比较与批量管理。
- 项目/分集/镜头级资产引用与提示词包查看/导出。

### V1 不做

- 不直接调用视频生成模型或平台 API。
- 不实现 ComfyUI、RunningHub、即梦/Seedance 的任务提交、轮询与回填。
- 不为尚未验证的语义检索需求提前部署独立向量数据库或知识库。
- 不做跨项目自动共享创意库。
- 不以自动生成替代用户定稿。

## 10. 从设计基线进入开发

整体产品流程、阶段/数据模型、后台与创作工作台、Agent/Model 管理、Skill Registry 和运行时协同已经形成可供 V1 开工的设计基线。后续不再为一般工程异常反复 Grill；未锁定的技术细节由 Codex 在实现前根据目标平台验证，并通过 Discovery 记录变更理由。

开发按可运行垂直闭环推进，而不是先做完所有页面：
1. 项目/工作区/SQLite 与项目隔离；
2. Idea/Concept 与 Episode 生命周期；
3. Artifact 草稿、不可变 Revision、阶段整体审批；
4. Agent Adapter、模型配置、Run 快照与安全隔离；
5. Skill Registry、八阶段 Profile、Skill Plan 与按需投射；
6. 一个阶段端到端创作闭环，再扩展 A1–B4 专业编辑器；
7. 资产/媒体、版本依赖、批量任务和 B4 导出。

详细任务、里程碑和验收见 [开发启动与实施路线图](./development-kickoff-and-implementation-roadmap.md)。

### 讨论方式

- 先由设计者给出完整方案和推荐，再由用户校准重要产品边界。
- 不为通用工程健壮性逐项发起选择题；异常处理、输入校验、日志、备份、文件完整性和基本恢复作为开发默认要求。
- 只对影响产品主流程、用户体验、核心数据身份/关系、长期架构锁定或 V1 范围的事项请求用户决策。
- 所有提案清楚标注「已确认 / 推荐草案 / 待确认」，不把建议冒充决定。

## 11. 开发前仍需验证的实现事项

以下事项不阻止开始搭建基础工程，但在对应里程碑进入实施前必须通过原型/测试验证：

1. 首个 Agent Runtime、官方 SDK/CLI 控制能力和本机隔离方案；凭据不能暴露给 Agent 子进程。

3. Runtime 动态模型发现和参数选择能力；不支持时使用 Runtime 默认模型。
4. 八个外部 Skill 的深度质量评测、License 范围审查和 CinePilot 输出适配；A4 通用 Screenwriter、B3 通用 Shot Designer 尚待补充/评估，B1/B2/B4 Skill 来源由用户后续补充。
5. 分镜图片 V1 先支持用户上传/预览/引用；实际图像/视频生成 API 不在本期范围。

这些是实现验证任务，不是继续拆成大量用户选择题的理由。涉及产品边界变化时再记录 Discovery/ADR。

## 0. 本轮设计范围

用户指出，上一版主要设计了 Agent 对话创作工作台，没有完整覆盖后台管理系统。本规格重新把产品界面拆成两个互相连接的功能区域：

1. **项目管理后台（Management Workspace）**：查看和管理系统内的项目、创意、分集、阶段、创作产物、版本、审批、素材资产、Agent 任务和系统配置。即使不打开 Agent 对话，也能找到、查看、编辑和追溯已经保存的内容。
2. **Agent 创作工作台（Creation Workspace）**：围绕当前项目/创意/分集/阶段展开对话创作，用户在与 Agent 交流的同时，能够查看当前阶段产物、定位具体内容、编辑局部对象、检查本次任务读取的依据、查看保存结果并完成阶段审查。

**两者共享同一套业务数据与 Python 服务，不是两个独立应用，也不维护两份内容。** Agent 在工作台提交的草稿，会立即进入管理后台的产物与版本管理；管理后台手动编辑产生的草稿，也能在创作工作台中继续交给 Agent 修改。

### 0.1 已确认的产品硬约束

- Vue + Python + Electron；Web 与 Electron 复用同一套核心工作台。
- 所有项目共用一个系统级 SQLite；项目创作正文、结构化文件和媒体仍保存在各自项目目录。
- 新建项目即创建项目目录与项目隔离 Agent 工作区；Agent 不可访问其他项目目录、全局 SQLite 和系统凭据。
- A1 点子发现、A2 创意发散属于项目级创意池；用户选中 Concept 并决定开发时才创建 Episode。
- 一个 Episode 对应一条独立短视频，并且有且只有一个主创意来源。
- 分集正式阶段为 A3 故事、A4 剧本、B1 导演、B2 制作拆解、B3 分镜、B4 提示词。
- Scene 与 Segment 独立管理；一个 Scene 可映射多个 Segment；每个 Segment 只有一个来源 Scene。
- Segment 可直接包含 Shot，或通过最多一层 Subsegment 组织 Shot；同一 Segment 不混用直属 Shot 与 Subsegment。
- 项目级基础资产可供本项目多集复用；Episode 可以创建自己的造型、服装和状态变体。
- 正式审批与交接以阶段为单位；Scene、Segment、Shot 可单独编辑和定点让 Agent 修改，不设置逐镜头独立审批。
- 已定稿版本不可覆盖；修改形成新草稿，用户确认后产生新定稿；上游版本变化标记下游待复核，不自动重做。
- Handoff 精简并绑定准确上游版本；Agent 通过受控接口按需读取内容，不把所有聊天和全部文档默认塞进上下文。
- V1 做到提示词和影视生成准备包，不接实际图片/视频生成服务或视频生成 API（已有图片素材的上传、预览、引用属于资产管理，不等于生成服务）。

### 0.2 本轮不做什么

本轮只定义页面有哪些、各页面管理什么数据、用户可以做什么、页面如何衔接，以及 Agent 对话时产物如何同步展示。

**明确不设计：**
- 色彩、字体、图标风格、视觉品牌、圆角、阴影、动效等视觉规范；
- 高保真 UI 稿、像素级布局、响应式断点、组件库最终选择；
- 最终 URL、REST 请求体、OpenAPI、数据库 DDL 和完整 JSON Schema；
- 实际视频生成 API、ComfyUI/RunningHub/Seedance 接口；
- 尚未确认的多用户组织、角色权限和团队协作规则。

以上属于后续 UI/UX 与技术实施阶段。

## 1. 产品界面总分区

### 1.1 两个工作区域的职责边界

| 对比维度 | 项目管理后台 | Agent 创作工作台 |
|---|---|---|
| 核心问题 | 项目现在有什么、进展如何、哪些内容已保存/待审查/待复核？ | 当前要创作或修改什么？Agent 依据什么？产物如何实时查看？ |
| 主要对象 | Project、Idea、Concept、Episode、Artifact、Revision、Approval、Asset、Media、AgentRun | 当前 Project/Idea/Concept/Episode/Stage、当前 Artifact、Scene/Segment/Shot、当前 AgentRun |
| 主要操作 | 浏览、筛选、检索、归档、编辑、比较版本、查看依赖、审查定稿、导出、任务管理 | 对话创作、指定任务范围、查看/编辑产物、定点修改、确认草稿、阶段审查 |
| 是否依赖聊天 | 不依赖；产物必须可以脱离聊天历史独立查看和管理 | 对话是主要创作入口，但产物不能只存在聊天消息中 |
| 数据写入 | 通过 Python 统一业务服务 | 通过相同 Python 业务服务 |
| Agent 能否跨项目 | 后台可按用户权限管理项目；Agent 仍严格绑定单项目 | 当前 Run 只能访问所属项目授权内容 |

**重要原则：后台不是文件管理器。** 用户打开 A4 剧本时，应看到可阅读的剧本正文、场次目录和版本关系；打开 B3 时，应看到片段层级、镜头表、镜头详情和参考图，而不是仅显示 \`shots.json\` 文件名和原始 JSON 文本。原始 Markdown/JSON 可作为高级查看/导出能力，但不能是唯一查看方式。

### 1.2 推荐应用主导航

~~~text
CinePilot Studio
├── 工作台首页 / Dashboard
├── 项目管理 / Projects
│   ├── 项目列表
│   └── 项目空间
│       ├── 项目概览
│       ├── 创意池（A1/A2）
│       ├── 分集管理
│       │   ├── 分集概览
│       │   └── 分集创作工作台（A3–B4）
│       ├── 创作产物库
│       ├── 素材资产库
│       ├── Agent 任务
│       ├── 项目 Skills
│       ├── 活动与版本记录
│       └── 项目设置 / 导出
├── 审查中心 / Reviews
├── Agent 任务中心 / Agent Runs
└── 系统设置 / Settings
    ├── Agent Runtime
    ├── Skill Registry
    ├── 存储与备份
    └── 应用设置
~~~

这是功能导航建议，不要求首期所有入口都做成独立一级菜单。项目内功能可以用侧边导航、页签或详情页入口承载，具体 UI/UX 后续确定。

### 1.3 全局层与项目层的区别

- **全局层**关注系统中多个项目的概况、跨项目待审查任务、Agent 执行队列、Runtime 和 Skill 注册。
- **项目层**只查看当前项目内的创意、分集、资产、产物和运行记录。
- **分集层**聚焦一条短视频从 A3 到 B4 的阶段进度、产物与制作内容。
- **创作层**围绕当前阶段，提供 Agent 对话和产物查看/修改的工作闭环。

后台用户可通过全局项目管理入口切换项目；Agent Run 不继承后台用户的全局访问能力，必须由服务端绑定项目 ID 和允许访问的对象。

## 2. 全局管理页面

### 2.1 工作台首页 / Dashboard

**目标**：用户进入系统后，快速知道有哪些项目、哪些工作需要处理，而不是直接进入聊天窗口。

建议展示：
- 项目数量、最近访问项目、最近更新项目；
- 待审查的阶段产物数量；
- 已有下游内容待复核的数量；
- 正在执行、排队、已完成、失败/取消的 Agent Run 摘要；
- 最近完成的分集和最近更新的产物；
- 快捷入口：新建项目、继续上次创作、查看待审查、查看运行任务。

操作：
- 点击项目进入项目概览；
- 点击待审查项直接进入对应分集/阶段审查；
- 点击 Agent 任务进入 Run 详情；
- 首页的统计仅用于导航和概览，不替代具体项目内的状态与版本记录。

### 2.2 项目列表 / Projects

**目标**：集中管理全部项目。

列表信息建议：
- 项目名称、项目 ID、描述/创作方向；
- 创建时间、最近更新时间；
- 分集数量；
- 创意池 Idea/Concept 数量；
- 当前正在创作的阶段、待审查/待复核数量；
- 最近一次 Agent 活动；
- 项目状态（例如正常、已归档；具体枚举待实现）。

操作：
- 新建项目；
- 打开项目；
- 搜索/筛选/排序；
- 归档与恢复；
- 进入项目导出/备份；
- 查看项目工作区位置（后台管理信息；不要将宿主绝对路径暴露给 Agent）。

新建项目流程：
1. 填写项目名称、简介、创作方向等基本资料；
2. 选择项目要启用的 Skills（可先使用推荐组合，创建后仍可调整）；
3. 选择已配置的 Agent Runtime（没有配置时仍允许先建立项目与创意池）；
4. 创建 Project 记录、项目目录、项目 Agent 工作区和 Skill Binding；
5. 进入项目概览或创意池。

不应在创建 Project 时自动创建空 Episode。

### 2.3 全局审查中心 / Reviews

**目标**：把需要用户做决定的内容集中呈现，避免用户必须逐个项目寻找待审查产物。

分区建议：
- **待定稿**：Agent 已保存草稿，当前阶段必要产物齐备，等待用户审查；
- **待补充**：草稿已保存，但阶段必需产物或校验项尚未齐备；
- **下游待复核**：上游新定稿后，既有下游仍保留，但来源版本已变化；
- **最近已定稿**：近期通过的阶段和其采用的 Revision 集合。

每条记录显示：
- 项目 / 分集 / 阶段；
- 本次待审查的产物清单；
- 草稿基于的旧定稿版本；
- 上游来源版本摘要；
- Agent 任务来源与最近更新时间；
- 当前待处理原因。

操作：
- 打开阶段审查页；
- 查看草稿与旧定稿差异；
- 继续编辑或交给 Agent 修改；
- 通过整阶段定稿；
- 对下游待复核项选择沿用现有结果或创建修订（不自动重做）。

**阶段定稿是用户显式动作。** 全局审查中心只能导航到审查页面并调用统一审批服务，不另建一套审批状态。

### 2.4 全局 Agent 任务中心 / Agent Runs

**目标**：管理所有项目的 Agent 执行活动，回答“当前哪些任务在跑、它们产出了什么、是否需要我处理”。

列表信息：
- Run ID、项目、分集（可为空，A1/A2 项目级任务）、阶段；
- 任务目标与任务范围（例如整个阶段、Scene S03、Segment P05、Shot SH08）；
- Agent Runtime、主 Skill/辅助 Skill；
- 状态、开始时间、耗时、最近事件；
- 关联草稿产物与保存结果。

筛选：
- 项目、分集、阶段、Runtime、Skill；
- 运行状态、时间范围；
- 是否生成草稿、是否需要人工审查。

Run 详情建议包含：
- 任务目标和用户原始要求；
- Handoff 使用的上游定稿版本锚点；
- 本次启用的 Skill 及其版本；
- Agent 对话记录；
- 安全可展示的任务事件（读取了哪些对象、提交了哪个草稿、校验结果）；
- 已保存草稿与关联 Artifact；
- 执行状态、取消/重试/重新发起等操作（具体能力受 Runtime 支持）。

Agent Run 记录是执行历史；正式创作正文仍以 Artifact Revision 文件为准。

### 2.5 系统设置 / Settings

建议包含以下设置页，不要与项目设置混为一谈：

| 设置页 | 管理内容 | 作用范围 |
|---|---|---|
| Agent 接入管理 | Agent Runtime Registry、CLI/SDK 检测、Connection Profile、认证状态、能力发现、隔离资格 | 系统级 |
| Agent 模型配置 | Adapter 动态模型目录、参数 Schema、Agent Model Profile（Agent + Model + 参数组合） | 系统级 |
| Skill Registry | 外部来源、License/NOTICE、上游 Commit、Skill 版本、兼容性、安全审核、评测和启停 | 系统级 |
| 存储与备份 | 系统数据根目录、共享 SQLite、项目存储根目录、备份与恢复 | 系统级 |
| 应用设置 | 通用偏好、桌面端/服务端信息、诊断信息 | 系统级 |

系统 Agent Connection / Model Profile 与项目 Agent 执行策略分开；系统安装/登记某 Skill 不代表所有项目自动启用。Agent 凭据不得复制到项目工作区；Skill 必须按项目启用并只读投射。

## 3. 项目管理后台页面

### 3.1 项目概览 / Project Overview

**目标**：提供项目级总览，作为项目管理后台的首页。

信息区域：
1. 项目基本信息：名称、简介、创作目标、创建/更新时间；
2. 创意池概况：Idea 数量、Concept 数量、待选择方向；
3. 分集概况：分集总数、各阶段进度分布；
4. 近期产物：最近保存的故事、剧本、导演方案、分镜、提示词；
5. 待处理事项：待定稿、下游待复核、Agent 任务需要处理；
6. 项目资产概况：角色、场景、道具等资产数量及最近更新；
7. 最近活动：项目内创建、编辑、保存、定稿、导出事件。

快捷操作：
- 新建 Idea；
- 进入创意池；
- 从已选 Concept 创建 Episode；
- 新建 Agent 创作任务；
- 查看全部分集；
- 查看全部产物/资产。

### 3.2 创意池 / Creative Pool（A1 + A2）

这是**项目级创意管理页面**，不属于任何 Episode。

页面需要同时支持两种对象，但必须明确区分：
- Idea：原始点子；
- Concept：从 Idea 发散出的独立候选创意方向。

建议页面功能：
- Idea 列表：按题材、情绪、关键词、创建时间、状态筛选；
- Idea 详情：查看原始描述、钩子、核心冲突、灵感来源和历史修改；
- Concept 列表：展示一个 Idea 派生的多个方向；
- Concept 比较：把多个方向的核心创意、人物关系、冲突、反转、结局、优势和风险并排比较；
- Concept 详情：查看完整方向方案、修改记录、当前状态；
- Agent 对话：围绕选中的 Idea 或 Concept 发散、深化、比较、重写；
- 复制创意：复制 Idea/Concept 内容作为新创作起点，明确由用户选择目标项目，不建立隐式跨项目共享关系；
- 归档/恢复：保留历史，不把暂时未选方向删除；
- 创建分集：用户选中某个 Concept 并明确决定进入视频开发后，创建 Episode，记录唯一 Primary Idea 和选中 Concept 来源。

创意池需要有独立的产物展示区：Agent 对话产生的 Idea/Concept 必须转成可保存、可查看、可编辑的卡片/正文对象；不能只留在聊天消息里。

### 3.3 分集列表 / Episodes

**目标**：管理项目下所有独立短视频。

列表字段建议：
- 分集名称/标题、Episode ID；
- 主创意 Idea 与选中 Concept；
- 内容类型/题材标签（若项目启用）；
- 当前正式阶段、当前阶段状态；
- 最近草稿、最近定稿时间；
- 待审查、待复核提示；
- Agent 任务状态。

功能：
- 新建分集（只能从已选 Concept 的立项流程创建；是否支持其他导入方式后续定义）；
- 打开分集概览；
- 按阶段、状态、题材、更新时间筛选；
- 复制分集（若未来支持，必须明确哪些创意来源和资产引用会复制；V1 不默认增加此功能）；
- 批量创建 Agent 任务（例如为多个分集分别生成 A4 剧本），每集独立 Run、独立草稿和独立定稿；
- 批量导出已定稿准备包。

批量操作不能合并不同分集的版本或审批状态。每个 Episode 仍独立推进、独立审查。

### 3.4 分集概览 / Episode Overview

**目标**：用户进入单集后先看到这条视频整体做到了哪一步，而不是立即被送进聊天。

信息区域：
1. 分集基本信息；
2. 主创意 Idea、选中 Concept 及当时采用的来源版本；
3. 故事简介/当前定稿梗概；
4. A3–B4 阶段进度总览；
5. 当前阶段与下一个可进入阶段；
6. 各阶段最新定稿/草稿和待审查状态；
7. 下游待复核提醒；
8. 本集资产使用摘要和变体；
9. 最近 Agent Run；
10. 最近活动与版本更新。

操作：
- 进入任意已开放阶段的创作工作台；
- 打开某阶段已保存产物；
- 查看阶段审查与版本历史；
- 查看本集资产；
- 查看本集全部产物；
- 启动批量/单项 Agent 任务；
- 导出本集已完成内容。

**阶段状态展示建议分开表达两个维度：**
- 产物生命周期：未开始 / 草稿中 / 待审查 / 已定稿；
- 来源新鲜度：正常 / 待复核。
上游变化后，不应把历史已定稿记录改成“未定稿”；应表达“已定稿，但基于旧上游，待复核”。具体枚举后续实现。

### 3.5 分集阶段进度 / Stage Overview

从 Episode Overview 点击阶段，可以先进入阶段管理页，而不是直接打开 Agent 聊天。

页面内容：
- 阶段目标和阶段说明；
- 阶段准入条件：哪些上游阶段已定稿、采用哪些版本；
- 本阶段必需产物与可选产物清单；
- 当前草稿、当前定稿、历史版本；
- 关联 Agent Run；
- 阶段级质量检查结果；
- 需要用户处理的事项；
- 下游依赖和可能影响范围；
- 「进入创作工作台」「查看产物」「审查并定稿」入口。

管理后台应允许用户只浏览阶段成果，不强制启动 Agent。

### 3.6 创作产物库 / Artifact Library

**目标**：这是管理后台的核心页面之一。集中管理已保存的所有创作成果，让用户不依赖聊天历史也能找到任何创意、剧本、导演方案、拆解、分镜或提示词。

#### 产物列表

可按以下条件筛选：
- 项目 / Episode；
- 阶段 A1–A2 或 A3–B4；
- 产物类型（Idea、Concept、Story、Screenplay、Director Plan、Breakdown、Shot Plan、Prompt Package 等）；
- 草稿/定稿/待复核；
- 创建/更新时间；
- Agent 生成或用户编辑；
- 是否有关联的上游版本变化。

列表至少显示：
- 产物名称、类型、所属项目/分集/阶段；
- 当前草稿和最新定稿版本；
- 状态和待复核提示；
- 最近修改时间；
- 关联 Agent Run；
- 关键来源版本。

#### 产物详情

详情页不应只是显示文件名。需要：
- 产物基本信息和所属关系；
- 按对应类型渲染的可读正文或结构化编辑视图；
- 当前版本、草稿、历史定稿的切换；
- Markdown 正文和 JSON 结构对象的统一内容视图；
- 版本差异；
- 来源与依赖关系；
- 关联资产与媒体预览；
- Agent 生成记录和用户修改记录；
- 打开对应阶段工作台；
- 导出原始 MD/JSON 或可读格式。

#### 管理后台直接编辑

允许用户不打开 Agent 聊天，直接在产物详情中编辑正文、字段、场次、片段或镜头。编辑必须：
1. 基于指定版本创建草稿；
2. 通过同一个 ArtifactService 保存；
3. 保留旧定稿；
4. 在阶段审查中纳入这次修改；
5. 用户完成阶段整体审查后才产生新定稿。

管理后台编辑与 Agent 修改使用同一份草稿/版本机制，不能有第二套绕过审批的保存方式。

### 3.7 素材资产库 / Asset & Media Library

**目标**：集中管理项目级角色、场景、服装、道具、风格与参考媒体，并清楚展示各分集实际使用的版本和变体。

资产分类：
- 角色 Character；
- 场景/地点 Location；
- 服装 Costume；
- 道具 Prop；
- 视觉风格 Style；
- 其他项目内参考资产。

资产列表：
- 资产名称、类型、缩略图；
- 当前基础版本；
- 被哪些分集使用；
- 是否存在分集变体；
- 最近更新时间。

资产详情：
- 基础身份与描述；
- 版本历史；
- 图片/媒体集合；
- 图片用途标签（角色面部特写、正面、侧面、背面、服装、表情等，具体标签可扩展）；
- 被哪些 Episode、Scene、Segment、Shot 引用；
- 相关 Agent Run 和创建/修改记录。

分集变体：
- 查看某 Episode 对某基础资产选择的版本；
- 查看本集专用服装、造型、状态或其他变体；
- 新建/编辑本集变体；
- 查看镜头具体使用哪个变体和媒体视图；
- 不允许编辑分集变体时意外修改项目基础资产。

媒体管理：
- 上传已有图片/参考图；
- 预览、分类、标注用途；
- 查看媒体被哪些资产和镜头引用；
- 通过媒体 ID 关联内容，不以图片文件名作为业务关联主键。

### 3.8 项目 Skills / Stage Skill Profiles

**目标**：管理项目 A1–B4 八个阶段分别采用哪些专业 Skill，以及题材插件和审查能力如何组合。

每个阶段分别展示：
- 主 Skill（允许暂时为空，并显示能力缺口）；
- 辅助 Skill；
- 条件/题材 Skill 及触发条件；
- Review Skill；
- 每个 Skill 的 CinePilot 版本、来源和 Runtime 兼容状态；
- 调用策略（必需、推荐、按需、禁用）与执行顺序。

操作：
- 从系统推荐模板初始化项目阶段配置；
- 启用/禁用 Skill、调整主/辅/条件/审查角色；
- 固定 Skill 版本；
- 设置题材插件触发条件；
- 查看 License、上游来源、NOTICE、改造差异和回归评测；
- 为特定分集的特定阶段建立覆盖配置；
- 查看历史 Agent Run 实际采用的 Skill Plan。

系统 Skill Registry 与项目 Stage Skill Profile 必须分开：系统登记某 Skill 不代表项目自动启用；项目配置不直接安装任意外部脚本。具体 Registry 和路由规则见 [Skill Registry 与阶段编排规格](./stage-skill-orchestration-and-registry.md)。

### 3.9 项目活动与版本记录 / Activity

按时间线查看项目内：
- Idea/Concept 创建与修改；
- Episode 创建；
- 阶段草稿保存；
- 阶段定稿；
- Agent Run 启动、完成、失败、取消；
- 上游变化引发的下游待复核；
- 资产新增、变体创建、媒体上传；
- 导入、导出和归档操作。

活动记录用于追溯“何时发生了什么”，不替代 Revision、StageApproval 和 AgentRun 的正式业务记录。

### 3.10 项目设置、归档与导出

建议管理：
- 项目名称、描述和创作默认约束；
- 项目启用 Skills；
- 默认 Agent Runtime（若有）；
- 项目目录位置的只读信息；
- 项目归档/恢复；
- 项目完整导出与导入。

由于所有项目共用一个 SQLite，项目迁移不能只复制项目文件夹。导出包需要由业务服务一并打包该项目的 MD/JSON/媒体和相关 SQLite 元数据（对象关系、版本、审批、依赖等）。该功能是项目管理能力，不允许 Agent 自行复制全局数据库。

## 4. Agent 创作工作台：通用页面结构

### 4.1 创作工作台的定位

创作工作台不是整个后台。它是从项目创意池、分集阶段或产物详情中打开的专门创作界面。

工作台必须解决四个并行任务：
1. 用户知道自己正在为哪个项目、哪个分集、哪个阶段创作；
2. 用户知道 Agent 本次任务的目标和作用范围；
3. 用户可以一边对话，一边查看/编辑当前阶段实际保存的产物；
4. 用户可以追溯 Agent 使用的输入版本，并明确决定是否把阶段定稿。

### 4.2 工作台信息区（功能，不规定视觉排版）

无论具体布局如何，页面必须具备以下功能区域：

**A. 当前工作上下文**
- Project 名称与项目入口；
- 当前 Idea/Concept 或 Episode；
- 当前阶段代码与名称；
- 阶段准入状态和上游定稿情况；
- 当前正在编辑的 Artifact / Scene / Segment / Shot；
- 当前草稿基于的定稿版本；
- 待复核提示。

**B. 阶段导航**
- 创意池工作台显示 A1 Idea / A2 Concept；
- Episode 工作台显示 A3 故事、A4 剧本、B1 导演、B2 制作拆解、B3 分镜、B4 提示词；
- 每个阶段显示当前生命周期状态和待复核标记；
- 未满足准入条件的阶段可以查看原因，但不能将未定稿上游作为正式输入；
- 切换阶段前，提示未保存的局部编辑并按统一草稿机制处理。

**C. 当前阶段产物目录**
- 显示本阶段所有必需/可选 Artifact；
- 每个 Artifact 显示草稿、最新定稿、待审查、待复核等状态；
- 可在不同产物间切换；
- 多文件产物（例如 Markdown 正文 + JSON 场次索引）应作为同一逻辑产物或阶段所需产物组合展示；
- 能打开完整内容、局部结构和历史版本。

**D. 产物查看与编辑区**
- 根据产物类型渲染专用内容视图；
- Markdown 正文提供可读与编辑模式；
- JSON 结构提供表格、树、卡片、字段表单等结构化视图；
- 支持按 Scene、Segment、Subsegment、Shot 定位；
- 支持局部编辑和 Agent 定点修改；
- 保存草稿后显示真实保存状态与 Revision/Draft 引用；
- 原始文件查看/下载作为辅助入口，而非主要 UI。

**E. Agent 对话区**
- 展示当前项目/分集/阶段的会话；
- 输入用户创作要求、修改要求和审查要求；
- 明确本次任务范围：当前阶段、指定 Artifact、指定 Scene、指定 Segment、指定 Shot；
- 展示 Agent 运行状态和任务事件；
- Agent 回复可关联到具体产物或局部对象；
- 用户可把某条建议应用到草稿，但不能把普通聊天文本自动当作已保存内容。

**F. 上下文与来源面板**
- 展示本次任务使用的上游已定稿版本；
- 展示系统预置的关键约束；
- 展示 Agent 本次按需读取过的对象摘要（Scene、Segment、Asset、Media 等）；
- 可以点击来源 ID 查看对应版本；
- 不把完整文件或全部聊天内容默认展开；
- 不允许 Agent 自己切换到其他项目。

**G. 版本、审查与阶段定稿**
- 当前草稿基于哪个旧定稿；
- 查看旧定稿与草稿差异；
- 查看阶段必需产物是否齐备；
- 展示结构校验和质量检查建议；
- 显示当前下游依赖；
- 用户显式点击整阶段定稿；
- 定稿后保留旧版，并开放符合准入条件的下游阶段。

### 4.3 对话和产物必须双向联动

这是创作工作台最重要的交互要求：

- 用户在产物区选中 Scene S03 后，对话输入框/任务区明确显示“当前目标：S03”；
- 用户选中 Segment P05，要求 Agent 重新规划时，Handoff 只带 P05 和必须的上游依据；
- 用户选中 Shot SH08 要求改运镜，Agent 只修改对应草稿对象，不重写整集镜头；
- Agent 回复中提及产物对象时，可以点击跳转到对应内容；
- Agent 提交草稿后，产物区刷新并定位到发生变化的对象；
- 产物区手动修改后，Agent 后续任务读取的是当前草稿或用户明确选择的已定稿版本，不允许静默使用错误版本；
- 对话记录保留用于追溯，但下游 Handoff 只使用系统指定的版本锚点和必要上下文。

**“已生成”与“已保存”必须区分。** 模型流式输出只是对话；经业务服务校验并持久化后才显示为已保存草稿；用户显式定稿后才显示为正式阶段成果。

### 4.4 Agent 会话与任务的关系

推荐按 Project / Idea 或 Episode / Stage 组织会话入口；一次 Agent Run 对应一次明确执行任务。一个会话可以先后有多次 Run，不能把一个很长的会话当作唯一上下文。

任务启动时显示：
- 任务类型（新建、续写、修改、审查、整理、批量任务）；
- 目标范围；
- 使用的 Skill；
- 输入版本锚点；
- 输出目标 Artifact；
- 是否允许读取图片/媒体；
- 本次任务提交后预期影响的范围。

任务结束后，用户可在同一工作台继续讨论；下一次任务仍由系统重新组装精简 Handoff，不默认把历史对话全量喂给模型。

### 4.5 阶段审查与定稿入口

工作台必须提供明确的“阶段审查”视图，不能只在对话中让用户说“定稿吧”。

审查视图包括：
- 本阶段所有必需产物；
- 当前拟定稿的具体 Revision；
- 本阶段输入来源版本；
- 结构校验结果；
- 缺失项/冲突项/待确认项；
- Agent 质量审查建议（可选，不能代替用户判断）；
- 与上一版定稿的变化；
- 下游会使用哪些内容；
- 定稿确认操作。

用户审查的是**阶段所采用的完整产物版本集合**，不是逐个 Scene/Shot 分别审批。某些阶段若只有一个必需 Artifact，也仍按阶段整体发布。

## 5. 各阶段工作台必须提供的专用内容视图

本节定义每阶段内容呈现和操作需求。具体控件样式后续 UI/UX 设计。

### 5.1 A1 点子发现（项目级）

页面对象：Idea。

需要展示：
- 点子标题/一句话钩子；
- 核心创意描述；
- 题材/类型、情绪、受众、冲突/反差、可拍性等可配置属性；
- 灵感来源或用户备注；
- 从该 Idea 派生的 Concept 列表；
- 最近修改和 Agent 任务。

操作：
- 创建/导入/编辑 Idea；
- 让 Agent 生成更多点子或优化现有点子；
- 将选中 Idea 发散成多个 Concept；
- 比较不同 Idea；
- 归档/恢复；
- 复制 Idea 内容到另一个项目（用户显式执行，不形成跨项目共享引用）。

### 5.2 A2 创意发散与筛选（项目级）

页面对象：Concept。

需要展示：
- 来源 Idea；
- 每条 Concept 的核心钩子、人物/目标、核心冲突、关键转折、结局方向；
- 与同 Idea 其他 Concept 的差异；
- 受众、情绪、题材、时长倾向等信息（具体字段后续确定）；
- Agent 对各方向的优缺点/风险分析；
- 修改历史和用户选择状态。

操作：
- 对一个 Idea 生成多条差异明显的方向；
- 对比两条或多条 Concept；
- 选中 Concept 交给 Agent 深化；
- 编辑、重命名、归档、复制；
- 用户明确选定方向后创建 Episode。

A1/A2 页面不显示 A3–B4 的分集阶段审批流程。

### 5.3 A3 故事深化与结构设计

需要展示：
- 当前选中 Concept 的来源摘要；
- 故事核心/Logline；
- 故事梗概；
- 人物目标、人物关系与人物变化；
- 核心冲突与冲突升级；
- 故事节拍/节点结构；
- 转折与结局；
- 预期时长或节奏说明（若产物提供）。

内容视图建议：
- 故事正文阅读/编辑；
- 节拍结构列表或可排序节点；
- 人物与关系查看；
- 关键冲突/转折摘要；
- 必需/可选产物目录。

操作：
- 让 Agent 生成或深化故事；
- 选择特定节拍让 Agent 修改；
- 调整节拍顺序和内容；
- 对比 Concept 与当前故事；
- 直接编辑正文或结构字段；
- 审查 A3 产物并整体定稿。

### 5.4 A4 文学剧本

需要展示：
- 剧本正文；
- Scene 场次目录；
- 场次编号、标题/内外景、时间、地点、出场角色等结构化信息；
- 当前选中场次的正文、动作、对白；
- 场次与 A3 故事节点的来源关系（如有）；
- 角色/地点/道具引用；
- 剧本总时长或场次统计（若可计算）。

操作：
- 全文阅读/编辑；
- 按 Scene ID 快速定位；
- 单场次局部编辑；
- 选中场次交给 Agent 续写、压缩、改对白或调整动作；
- 场次顺序和结构信息维护；
- 检查场次索引与 Markdown 正文是否一致；
- 比较剧本版本；
- 审查 A4 并整体定稿。

Markdown 正文与 \`scenes.json\` 必须保持字段权威清晰；界面可以统一呈现，但不能让正文和 JSON 各自独立维护一份完整剧本。

### 5.5 B1 导演阐述与视听设计

需要展示：
- 导演阐述正文；
- 作品总体视觉风格和影像基调；
- 摄影、景别、机位、运动、构图原则；
- 表演方向、节奏、情绪和声音方向；
- 场次级导演重点；
- 项目风格与本集风格引用；
- 相关视觉参考媒体（若已上传）。

操作：
- 让 Agent 生成/深化导演方案；
- 修改全局视听原则或某个场次的导演意图；
- 查看被引用的角色、场景、风格资产；
- 检查导演方案与剧本冲突；
- 审查 B1 并整体定稿。

### 5.6 B2 制作拆解

需要展示：
- A4 Scene 场次清单；
- Scene 与 Segment 的映射关系；
- Segment 树；
- 可选的 Subsegment；
- 每个 Segment 的唯一来源 Scene；
- 每个 Segment/Subsegment 的目标、内容摘要、情绪/动作重点；
- 本集资产需求和引用；
- 未关联或缺失的角色、场景、服装、道具；
- Segment 的结构模式（直属镜头或子片段）。

推荐提供几种内容视图：
- 场次映射表：便于检查一个 Scene 对应哪些 Segment；
- 片段树：便于查看 Segment/Subsegment 层级；
- 资产需求表：按片段核对人物、场景、服装、道具；
- 片段详情：查看来源 Scene 和内容约束。

操作：
- 从某 Scene 拆分一个或多个 Segment；
- 调整 Segment 顺序；
- 为复杂 Segment 建立最多一层 Subsegment；
- 修改来源 Scene（必须经过关系校验）；
- 绑定/查看资产需求；
- 让 Agent 对指定 Scene 或 Segment 做拆解；
- 检查无来源、错误归属、层级超过一层或混合直属 Shot/Subsegment 等结构问题；
- 审查 B2 并整体定稿。

### 5.7 B3 分镜与镜头规划

需要展示：
- 已定稿 B2 的 Segment/Subsegment 树；
- 每个叶级单元包含的 Shot；
- 镜头顺序、编号、时长；
- 景别、机位、构图、摄影机运动；
- 镜头内角色动作、表演、环境变化；
- 镜头衔接和连续性；
- 使用的角色/场景/服装/道具版本；
- 相关参考图片或用户上传的分镜/关键帧素材。

推荐提供互相关联的视图：
- **镜头列表/表格**：适合快速检查顺序、时长、景别、运镜；
- **镜头卡片**：适合逐镜头阅读动作、构图和资产引用；
- **分镜网格/序列视图**：适合查看整段视觉连续性；没有图片时以文字镜头卡占位，不代表自动生成分镜图片；
- **片段树**：从 Segment/Subsegment 切换镜头组；
- **镜头详情**：编辑单镜头字段、查看资产多视图和来源。

操作：
- 按片段生成镜头草稿；
- 选中一个或多个 Shot 让 Agent 定向修改；
- 手动编辑 Shot 字段；
- 调整顺序、时长和归属；
- 查看镜头之间的连续性；
- 检查 Shot 是否归属合法叶级单元；
- 查看角色/场景图片引用；
- 审查 B3 并整体定稿。

**本期不要求内建分镜图像生成。** 现有图片上传、预览和引用可支持工作台展示；未来图像生成作为单独能力接入。

### 5.8 B4 视频生成提示词

需要展示：
- 每个 Shot 对应的 Prompt；
- Prompt 与 B3 Shot ID / 定稿版本的对应关系；
- 角色、场景、道具、风格引用；
- 动作、镜头、连续性约束；
- 负面限制或模型无关注意事项（如产物定义包含）；
- 全集提示词清单和缺失项；
- 提示词版本与修改历史。

操作：
- 为整集或指定片段/镜头生成提示词；
- 单条 Prompt 局部修改；
- 批量检查 Prompt 是否覆盖全部必需 Shot；
- 对比 Prompt 与镜头设计是否一致；
- 复制单条 Prompt；
- 导出整集提示词包/制作准备包；
- 审查 B4 并整体定稿。

B4 的导出是 V1 交付终点；不直接触发视频生成任务。

## 6. 内容浏览、编辑、版本和审批的统一规则

### 6.1 管理后台与工作台共用同一内容服务

- 从创作工作台编辑 A4 Scene，和从产物库编辑 A4 Scene，最后写入同一个 Artifact Draft。
- 从资产库修改角色描述，和从镜头资产侧栏修改角色描述，必须区分是在改项目基础资产还是 Episode Variant。
- Agent 提交草稿、用户手动编辑、管理后台修改，都走同一服务校验和版本机制。
- 任何页面都不能直接修改已定稿文件或绕过 SQLite 审批记录。

### 6.2 产物查看模式

建议每个 Artifact 具备：
- 阅读模式；
- 编辑模式；
- 结构化模式（适用 JSON）；
- 原始文件模式（辅助）；
- 版本历史模式；
- 来源/依赖模式。

不同产物不必强制提供全部模式。例如长剧本以正文阅读/编辑为主，Shot Plan 以镜头表/卡片/树为主。

### 6.3 草稿与定稿展示

至少区分：
- 当前草稿；
- 当前正式定稿；
- 历史正式定稿；
- 上游变化后待复核的下游定稿。

用户打开产物时，默认清楚显示当前看的是什么版本，不能把最新草稿误显示成正式定稿。

### 6.4 版本差异

建议按内容类型提供差异：
- Markdown：正文差异、场次增删/调整；
- Story/Breakdown JSON：节点增删、顺序变化、字段变化；
- Shot Plan：镜头新增/删除、顺序、动作、运镜、时长、资产引用变化；
- Prompt Package：逐镜头 Prompt 差异、引用变化；
- Asset：基础设定、变体、图片用途变化。

差异视图用于辅助用户审查，不自动决定内容是否正确。

### 6.5 阶段整体审查

审查中心与工作台均使用相同阶段审批能力：
- 当前阶段必需产物是否齐备；
- 采用的具体 Revision 集合；
- 上游输入版本；
- 结构校验；
- Agent 辅助质量检查；
- 与上次定稿的差异；
- 下游依赖；
- 用户定稿动作。

局部 Scene/Shot 修改不会创建独立审批状态，但必须纳入本阶段草稿与阶段审查。

## 7. 页面之间的主要导航与操作流程

### 7.1 从项目到创意方向

~~~text
项目列表
  → 新建项目 / 打开项目
    → 项目概览
      → 创意池
        → Idea 详情
          → Agent 发散
            → Concept 列表 / 比较 / 详情
              → 用户选择方向并创建 Episode
~~~

### 7.2 从分集到阶段创作

~~~text
分集列表
  → Episode 概览
    → 阶段进度
      → 阶段管理页
        ├─ 查看产物（不启动 Agent）
        ├─ 版本历史/来源依赖
        ├─ 阶段审查
        └─ 进入 Agent 创作工作台
             ├─ 对话创作
             ├─ 查看产物
             ├─ 选中局部对象修改
             ├─ 保存草稿
             └─ 阶段整体定稿
~~~

### 7.3 从管理后台独立查看产物

~~~text
项目空间
  → 创作产物库
    → 筛选 A4 / B3 / B4 等产物
      → 打开产物详情
        ├─ 阅读/编辑
        ├─ 查看 Revision 历史
        ├─ 查看来源与依赖
        ├─ 查看关联 Agent Run
        └─ 打开对应阶段创作工作台
~~~

此流程保证产物管理不依赖聊天入口。

### 7.4 从 Agent 任务回到产物

~~~text
Agent 任务中心
  → Run 详情
    → 查看 Handoff / Skill / 输入版本 / 事件
      → 打开已保存草稿
        → 产物详情 / 阶段审查
          → 用户定稿
~~~

## 8. 搜索、筛选、批量操作与全局信息

### 8.1 全局搜索（管理后台）

建议搜索范围：
- 项目名称/ID；
- Idea / Concept 标题与文本；
- Episode 标题；
- Artifact 名称、类型、阶段；
- Scene / Segment / Subsegment / Shot ID；
- Asset 名称与类型；
- Agent Run ID。

全文检索可以后续由 SQLite FTS 或专门索引支持；初期至少应实现稳定 ID、标题、类型、状态和关系查询。

全局管理后台可以按用户可见范围搜索多个项目；**Agent 运行时不得使用该全局搜索**，只能通过项目绑定的受控查询工具访问当前项目和正式允许的来源。

### 8.2 项目内搜索

项目内搜索应支持：
- Idea/Concept；
- Episode；
- 阶段产物；
- 场次、片段、镜头；
- 资产、媒体；
- Agent Run 和活动记录。

搜索结果应显示对象类型和所属路径，并可直接跳到对应详情/工作台。

### 8.3 批量操作

V1 值得支持的批量能力：
- 为多个 Episode 创建同一阶段的独立 Agent Run；
- 批量查看任务状态和已保存结果；
- 批量导出符合条件的已定稿准备包；
- 批量归档项目或创意对象（需二次确认的破坏性操作不在本轮定义）。

**不允许批量任务合并上下文和定稿**：每个 Episode 独立 Handoff、Run、草稿、版本与审批。批量只是任务发起和结果管理的便利入口。

## 9. 必须覆盖的页面状态

这不是视觉规范，但功能规格必须确保页面能表达下列状态：

| 场景 | 页面应表达什么 | 允许的用户动作 |
|---|---|---|
| 新项目，没有 Idea | 创意池为空，可开始创建/导入 Idea | 新建 Idea、发起点子任务 |
| 有 Idea，没有 Concept | 点子已保存，尚无候选方向 | 发散 Concept、编辑 Idea |
| 有 Concept，没有 Episode | 候选方向待选择 | 比较、修改、归档、创建 Episode |
| Episode 刚建立 | A3 尚未开始，A1/A2 来源可回溯 | 进入 A3 创作 |
| 上游未定稿 | 下游阶段显示准入条件未满足 | 查看原因、返回上游；可自由讨论但不能正式交接 |
| Agent 未配置 | 项目和内容管理可用，但无法启动 Agent Run | 进入系统设置配置 Runtime |
| Agent 运行中 | 任务事件和流式回复；未保存内容明确标为临时输出 | 等待、取消、继续查看 |
| Agent 已输出但未保存 | 不能误标为正式草稿 | 通过受控提交/保存动作生成草稿 |
| 草稿已保存待审查 | 展示准确草稿版本和基础定稿 | 打开差异、继续编辑、阶段审查 |
| 阶段已定稿 | 展示被采用的 Revision 集合和定稿时间 | 查看、导出、创建下一阶段任务 |
| 下游待复核 | 保留旧定稿，说明上游哪个版本变化 | 查看差异、沿用或创建修订 |
| 某阶段有多份产物 | 清楚展示必需/可选产物及各自版本 | 逐项查看，整阶段定稿 |
| 任务失败/取消 | 保留 Run 记录和已保存草稿（若有） | 查看详情、重试或新建任务 |
| 资产缺失/媒体不可用 | 显示缺少的资产或图片引用 | 补充资产、替换引用、返回相关阶段 |
| 已有完整历史版本 | 可切换当前定稿与旧版 | 对比、从旧版派生新草稿 |

## 11. V1 页面实现优先级建议

建议按**真实使用闭环**分期，不必首期把每一个管理页面都做成完整复杂模块。

### P0：必须形成可用闭环

1. 项目列表、新建项目、项目概览；
2. 创意池：Idea/Concept 列表、详情、Agent 对话、选择 Concept 创建 Episode；
3. 分集列表、分集概览、A3–B4 阶段导航；
4. 通用创作工作台：对话 + 产物目录 + 内容查看/编辑 + 上下文来源；
5. Artifact Draft 保存、版本历史、阶段整体审查/定稿；
6. Agent Run 状态、任务记录和已保存产物回链；
7. 项目基础资产/图片上传、预览和分集变体的最低可用能力；
8. 系统 Runtime 配置和项目 Skill 启用。

### P1：增强后台管理和专业编辑体验

1. 完整创作产物库及多类型详情页；
2. 全局审查中心；
3. 全局 Agent 任务中心及事件详情；
4. Scene / Segment / Subsegment / Shot 专业结构编辑器；
5. 资产引用关系、媒体用途与变体管理；
6. 版本差异、来源依赖图和待复核工作流；
7. 项目活动时间线、批量任务和批量导出。

### P2：后续效率与扩展

1. 全文搜索与高级筛选；
2. 更完善的项目导入/导出、备份恢复；
3. 多项目创作模板与项目初始化模板；
4. 更复杂的批量工作流和任务调度；
5. 多用户/团队权限（若未来确有需求）；
6. 图片/视频生成服务接入（不属于当前 V1）。

优先级是开发建议，不代表用户已经批准删减 V1 功能。若某项 P1 是当前主流程的必要条件，应在实际开发拆分时前移。

## 12. 本规格的验收标准

页面功能设计完成后，应能回答以下问题并在后续实现中逐项验证：

1. 不打开 Agent 聊天，用户能否从项目后台找到并阅读一集已定稿剧本？
2. 用户能否从产物库找到某条 Shot，看到它属于哪个 Segment/Subsegment、来源哪个 Scene、使用哪个角色/服装版本？
3. 用户能否在管理后台直接编辑剧本或镜头，并将修改保存为草稿，而不是覆盖定稿？
4. 用户能否从分集概览看出 A3–B4 每个阶段当前状态、准入条件和待复核原因？
5. 用户在 Agent 对话中能否明确知道当前正在修改哪份产物、哪个 Scene/Shot？
6. Agent 提交草稿后，工作台和后台产物库能否查看同一个已保存版本？
7. 用户能否查看 Agent 本次任务使用的上游版本和相关资产，而不需要加载全部历史上下文？
8. 用户能否在一个阶段中局部修改多个 Scene/Shot，最后只进行一次阶段整体审查和定稿？
9. 用户能否在全局任务中心查看多个项目的 Agent Run，同时确保 Agent 本身仍然无法跨项目访问？
10. 上游版本变化后，后台能否定位受影响的下游定稿，保留旧结果并让用户选择如何处理？
11. Web 与 Electron 重新打开后，能否从同一业务服务恢复项目、产物、版本、审批和任务信息？
12. B4 定稿后，能否浏览和导出完整提示词/制作准备包，而不启动视频生成？

## 14. Agent 接入与模型管理页面

### 14.1 系统设置 → Agent 接入管理

列表显示每个 Runtime 的：
- 名称、接入类型（CLI / SDK / 远端 Agent Host）；
- 安装状态、版本、执行宿主；
- 认证状态（只显示状态，不显示凭据）；
- 最近能力检测时间；
- 隔离资格与测试状态；
- 模型发现能力和可用状态。

操作：
- 自动检测本机 Agent；
- 添加/编辑 Connection Profile；
- 认证或刷新认证状态；
- 测试连接；
- 查看能力声明；
- 启用/停用 Runtime。

### 14.2 Agent 详情 → 模型与参数

先选择 Agent Connection，再展示该 Adapter 实际发现的模型和支持参数：
- 模型 ID、展示名、Provider（可识别时）；
- 可用状态、能力来源、检测时间；
- 是否支持显式模型选择；
- 推理等级/输出参数的动态 Schema；
- Runtime 默认模型选项。

不支持模型发现时，显示“使用 Agent 默认模型”；不支持的参数不展示，不得硬编码统一模型列表。

### 14.3 Agent Model Profile 管理

用户可以把 Agent Connection + 模型选择 + Adapter 支持的参数保存为 Profile，例如“故事创作高推理”“批量整理快速模式”。Profile 不包含 Skill。

### 14.4 项目设置 → Agent 执行策略

项目可设置：
- 项目默认 Agent Model Profile；
- A1–A4、B1–B4 阶段级 Profile；
- 分集特定阶段覆盖；
- 单次任务启动前覆盖；
- 当前配置的继承来源与有效配置预览。

配置解析优先级为：任务覆盖 → 分集阶段覆盖 → 项目阶段配置 → 项目默认 → 系统默认。不可用模型或不支持参数应阻止启动并给出原因，不静默切换。

### 14.5 Agent Run 详情

显示实际执行的 Runtime/版本、Model/参数、配置来源、Skill Plan、Handoff 输入 Revision、沙箱策略和任务事件。敏感凭据不得展示或写入快照。

## 15. Skill Registry 与阶段配置页面

### 15.1 系统设置 → Skill Registry

列表展示 Skill 名称、来源仓库、入口路径、上游 Commit、License/NOTICE、作者、CinePilot 版本、适用阶段、Runtime 兼容、安全审查、评测状态和生命周期状态。

操作包括登记来源、查看来源审计、建立导入候选、提炼/改造、运行测试、启用/停用和查看版本历史。License 未核验的候选不得作为可导入 Skill 启用。

### 15.2 Skill 详情与来源审计

需要显示：
- 原始仓库和具体 Skill 路径；
- 原始作者、许可证和 NOTICE；
- 固定 Commit SHA 与入口文件 SHA；
- 导入的文件/依赖清单；
- 保留、删除、修改和新增的模块；
- CinePilot 改造版本与回归评测结果。

八个第一批候选来源及当前核验结果见 [Skill Registry 与阶段编排规格 §4](./stage-skill-orchestration-and-registry.md)。

### 15.3 项目设置 → 八阶段 Stage Skill Profiles

配置页固定展示 A1、A2、A3、A4、B1、B2、B3、B4 八个阶段。每阶段可以设置主 Skill、辅助 Skill、条件插件、审查 Skill、版本、调用策略和顺序。

当前推荐候选状态：
- A1：Story Idea Generator 主候选；Creative Director 辅助候选；
- A2：Short Film Development 主候选；Creative Director 辅助；Comedy/Stephen Chow 按题材触发；
- A3：Short Film Development 主候选；AI ShortVideo Story Engine 辅助候选；
- A4：通用 Screenwriter 待补充；Wind Comic Screenwriter 待评估；
- B1/B2/B4：待用户后续补充；
- B3：AI ShortVideo Story Engine / Wind Comic 待评估，不作为默认正式主 Skill。

此列表是候选状态，不代表已导入或已启用。

### 15.4 分集阶段覆盖

允许某个 Episode 的特定阶段覆盖项目配置，例如某集启用喜剧插件；修改只影响该分集，不改变项目默认 Profile。

### 15.5 当前任务 Skill Plan 预览

Agent Run 启动前展示主 Skill、辅助 Skill、条件触发结果、审查 Skill、版本、调用原因和 Runtime 兼容状态。用户可以覆盖可选 Skill。Run 启动后固定 Skill Plan 快照并显示在任务详情中。

> 日期：2026-10-30  
> 状态：**已确认事实**与**待确认的阶段合同建议**分开记录。此文档不是可直接执行的最终 JSON Schema。  
> 关联：[整体系统总览](./overall-product-workflow-and-system-map.md) · [领域词汇](../../CONTEXT.md) · [阶段准入 ADR-0009](../adr/0009-approved-upstream-stage-gates.md) · [精简 Handoff ADR-0010](../adr/0010-compact-versioned-agent-handoff.md)

## 1. 本文档要解决的问题

定义每一阶段的**业务目标、输入依据、必需产物建议、可选产物、用户审阅点、下一阶段使用的内容、UI 展示**，避免“生成了一个 Markdown 但下一个阶段不知道其中哪些是真正定稿的内容”。暂不讨论通用崩溃场景、异常兜底、消息队列或数据库字段细节。

### 已确认的硬约束

- 每个项目有自己的创意池；创意点子与独立创意方向存在于分集创建前，**选中方向并决定开发才创建分集**。
- 一集等于一条完整独立短视频，具有唯一主创意点子；各集可独立推进或按相同阶段批量推进。
- 同一分集的**正式下游阶段**必须建立在上游必要产物已定稿的前提上。
- 剧本场次与导演片段不同；一场次可拆多片段，每片段仅一个来源场次。镜头属于直属片段或最多一级子片段的叶节点。
- 已定稿产物不覆盖；修订产生新草稿，重新经用户确认定稿。上游更新仅将相关下游标记待复核，不自动重新生成。
- 系统预置 Handoff 必要目标、强制约束和版本锚点；Agent 从受控接口按需读取详细原文。
- Vue 前端、Python 后端和 Electron 桌面端已确认；SQLite 管关系/版本/审批、Markdown 管正文、JSON 管结构化产物，单字段唯一权威，经统一业务服务读写。
- V1 交付生成准备包，**不做实际视频生成**。

### 建议的阶段合同通用接口（概念层）

每个正式阶段推荐统一具备：
- **目标**：本阶段要解决的创作问题，不由技术数据格式替代。
- **输入**：必需的上游定稿版本 + 本集当前有效的角色、风格及用户约束。
- **正式产物**：可由 UI 展示和修改的明确产物，不只是 Agent 聊天回复。
- **审查清单**：结构完整性与关键内容质量检查；系统管确定性规则，Agent 可辅助质量建议，用户定稿。
- **输出引用**：ID、版本、来源场次/素材和下阶段可查询的具体内容。
- **状态**：草稿、定稿、被上游变化提示待复核等；具体数据库状态集合后续设计。

A1、A2 是项目级创意活动，不强制要求有分集或套用分集内阶段门禁。

## 2. A 系统：创意编剧

### A1 点子发现 / Idea Discovery（项目级）

**目标**：发现、产生和储备可继续发散的创意种子，不要求每个点子立即变成视频作品。

**输入**：用户描述的题材、IP/角色背景、受众、时长与风格意向；现有项目约束；Agent 的创意生成任务。

**建议产物**
- 必需：独立的**创意点子 Idea 卡**（稳定 ID、标题/一句话故事钩子、核心反差或冲突、简述、项目归属）。
- 建议可选：题材标签、情绪/看点、用户反馈、优先级、关联参考、不同来源的点子集合。

**UI**：项目创意池卡片、关键词筛选、详情编辑、复制内容、对 Agent 发起“基于这个点子继续发散”。

**进入下一步**：用户选择点子进行创意方向发散；不因生成点子自动创建分集。

**校验建议**：避免点子空白/重复 ID；不强制以大纲完整性审核点子。

### A2 创意发散与筛选 / Concept Exploration（项目级）

**目标**：对一个点子形成多条真正不同的候选方向，允许比较、保留、编辑和选择。

**输入**：点子当前指定版本或内容、项目风格约束和用户提出的差异化要求。

**建议产物**
- 必需：一个或多个**创意方向 Concept 卡**，具有稳定身份、来源 Idea、故事角度、主要人物目标、冲突/转折与结局设想。
- 建议可选：类型/基调、卖点、短视频可行性分析、候选对比、筛选理由。

**UI**：同一点子的多方向并排比较；继续改写、保留/归档、选中并创建分集。

**阶段出口（已确认）**：只有用户选择方向并明确开展独立视频开发，系统才创建 Episode，记录唯一主创意点子和所选方向。

**边界建议**：同一个方向是否允许创建多个独立分集、是否允许绕过方向直接创建分集，仍应单独产品确认；不默认做复杂复用关系。

### A3 故事深化与结构设计 / Story Development（分集正式阶段）

**目标**：把选定方向发展为有清晰因果、冲突升级、情绪节奏和结局的完整短视频故事。

**正式输入**：创建分集时选中的创意方向快照/引用、主创意点子、分集目标时长与体裁约束、项目内当前有效的角色/世界观规范。

**建议的必需产物**
1. **故事核心说明**：核心命题、主要人物及目标、故事冲突、结局落点。
2. **故事梗概**：完整的开端、发展、转折、结局，明确事件因果。
3. **结构/节拍表**：有序剧情节点，每节点说明目标、变化、冲突或情绪推进；初期可按短视频长度灵活控制数量。

**建议可选产物**：人物关系、背景世界设定、备选结局、节奏/时长估计、叙事风格说明。

**UI**：故事结构画布或卡片列表 + 文本梗概编辑器；旁边保留 Agent 对话和用户审阅意见。

**审查建议**：故事是否完整、冲突是否持续、动机是否成立、是否符合选中方向和短视频时长。系统验证节点/结构存在与排序；Agent 给出质量反馈，用户决定是否定稿。

**Handoff → A4**：输入故事定稿版本 ID、梗概与结构节点的读取索引、人物/风格约束；不将全部发散对话一并传入剧本阶段。

### A4 文学剧本 / Screenplay（分集正式阶段）

**目标**：把已定稿的故事结构转写为完整、可进行影视拆解的文学剧本。

**正式输入**：A3 已定稿故事/结构版本、角色与世界观约束。

**建议的必需产物**
1. **完整剧本正文**：场次标题、动作描述、必要对白与叙事推进（Markdown 为正文权威）。
2. **剧本场次索引**：稳定 Scene ID、顺序、场次摘要、人物/地点引用和对应正文位置（JSON 结构化权威）。
3. **创作约束摘要**：剧本风格、目标时长、关键不能修改的故事选择；引用已有权威约束而非另造可编辑副本。

**建议可选产物**：对白精修建议、旁白/声音说明、剧本预计时长、重要情绪节拍注释。

**UI**：剧本正文编辑器 + 场次目录 + 场次属性 + 版本对比；点击某场可以只将该场发给 Agent 定点修改。

**审查建议**：场次完整且顺序稳定，剧本与 A3 结局/人物目标一致，结构索引准确指向正文。用户定稿后允许进入影视制作系统。

**Handoff → B1/B2/B3**：提供完整剧本定稿版本锚点、场次列表摘要、关键约束；之后可按 Scene ID 查询正文，不默认在每次导演任务中传入全部场次。

## 3. B 系统：影视制作规划

### B1 导演阐述与视听设计 / Directorial Vision（分集正式阶段）

**目标**：解释“怎么拍、怎么演、什么节奏、什么视觉与声音风格”，把文学剧本转化为可指导后续制作拆解的导演方案。

**正式输入**：A4 已定稿剧本版本，按需读取 A3 结构、项目风格规范和已确认角色设定。

**建议的必需产物**
1. **导演阐述**：情绪目标、核心戏剧处理方式、主要人物表演方式。
2. **视听规范**：画风/写实程度、构图、光线/色彩、镜头运动与剪辑节奏原则。
3. **关键场次的导演处理重点**：哪些场次需要重点表演、视觉转折或强调镜头语言。

**建议可选产物**：声音与音乐方向、镜头参考、场次情绪曲线、导演术语词典、视觉参考图。

**UI**：导演方案文档、场次重点表、风格参考区；可对局部段落定点审查。

**审查建议**：有没有清晰且可用于实际分镜规划的视觉指导；不得与剧本定稿的重大情节矛盾。

**Handoff → B2/B3**：导演方案定稿版本、已确认的视听约束和按场次索引的导演重点。

### B2 制作拆解 / Production Breakdown（分集正式阶段，已确认）

**第十四项核心流程决定（已确认，2026-10-30）**：B2 是独立的正式「制作拆解」阶段，负责场次→片段/子片段映射及本集资产需求与引用清单；角色、场景、服装、道具等创作资产则作为贯穿 A3–B4 的横向能力，允许在故事、剧本、导演、拆解、分镜及提示词流程中逐步建立和完善，**不需要等到 B2 才能创建资产**。参见 [ADR-0014](../adr/0014-production-breakdown-with-cross-stage-assets.md)。

**目标**：把剧本场次映射为有序导演片段/可选子片段，核对本集所需的角色、场景、服装、道具及视觉参考。

**正式输入**：A4 剧本已定稿场次索引及 B1 已定稿导演方案；当前项目可用的资产清单。

**建议的必需产物**
1. **场次→片段映射**：每个导演片段有唯一来源剧本场次，允许一个场次拆为多个片段。
2. **片段/子片段计划**：有序片段、节拍目标、时长初估和叶节点层级；子片段最多一层，不混放直属镜头与子片段。
3. **本集素材需求清单**：每个制作单元需要哪些人物/场景/服装/道具/视觉约束；缺少资产时清晰标注待补，而非伪造已完成内容。

**建议可选产物**：片段冲突/情绪说明、资产参考图、关键动作/表演需求、制作难度或可生成性评估。

**UI**：剧本场次-片段映射面板、可折叠片段树、角色/场景资产关联卡、待补素材列表。

**审查建议**：所有已形成正式片段都有合法来源场次且属于本集；顺序与剧本一致或有明确导演处理说明；素材引用可定位，不要求 V1 每个资产都已生成图片。

**Handoff → B3**：片段层级的已定稿版本、来源场次、片段目标与资产引用；镜头设计按片段逐项展开。

### B3 分镜与镜头规划 / Storyboard & Shot Planning（分集正式阶段）

**目标**：将已确定的导演片段转化为每个镜头可理解、可审阅、可生成视频提示词的镜头级设计。

**正式输入**：B2 已定稿片段结构、B1 导演约束、A4 指定来源场次原文和相关角色/场景资产版本。

**建议的必需产物**
1. **镜头列表**：稳定 Shot ID、所在叶级片段或子片段、镜头顺序、目标时长。
2. **镜头语言**：景别、机位/角度、构图、运镜、光影与视线/空间关系等关键描述。
3. **表演与动作**：角色、动作起点/过程/终点、表情、互动、转场与连续性要求。
4. **素材引用**：镜头所用角色/场景等资产 ID 与当前约束，避免仅靠自由文本猜角色。

**建议可选产物**：分镜草图、关键帧图片或多视图参考、声音节奏提示、镜头内多个关键动作节点。

**UI**：片段树 + 镜头卡片/镜头表 + 镜头属性编辑区 + 参考图/分镜图栏；分镜图片缺席时也能以镜头文本完整展示。

**审查建议**：镜头完整且可理解、动作与运镜方向明确、镜头顺序和时长合理、角色与场景一致、源片段可追溯。

**Handoff → B4**：镜头表具体定稿版本、必要角色/场景引用、连续性规则。镜头可逐个作为提示词生成任务的输入，而非让 Agent 每次读取整集全部镜头。

**待确认的产品定义**：“分镜”是否仅指镜头卡/文字规划，还是必须从 V1 就管理图片/关键帧，及单镜头是否允许多帧视觉表达。目前仅推荐支持引用/上传已有图片、无需在 V1 内建图片生成。

### B4 视频生成提示词 / Video Prompt Package（分集正式阶段）

**目标**：把经过确认的镜头方案变成可供第三方 AI 视频生成工具使用的、结构可编辑的制作准备包，**但不执行生成**。

**正式输入**：B3 镜头规划已定稿版本、项目视觉风格、具体角色/场景/道具与表演约束。

**建议的必需产物**
1. **镜头级提示词**：每个镜头 ID 对应的主要内容提示词，动作、主体、环境、机位、运动、节奏等字段。
2. **一致性约束**：具体角色/服装、场景与视觉风格的引用；必要的连续性和禁改要求。
3. **整集制作清单**：镜头顺序、时长、资源引用、提示词、上游版本与必要说明，可浏览、复制或导出。

**建议可选产物**：模型专用提示词变体、负向限制、参数建议、分镜参考索引、多语言提示词。

**UI**：按镜头排列提示词、编辑/复制/批量导出、对照对应的分镜与上游导演约束。

**审查建议**：每条正式镜头是否有目标提示词、引用正确、未改变已定稿镜头主动作及角色、没有缺失必要连续性；最终形成用户确认的制作准备包。

**V1 终点**：导出准备包，交给视频生成流程或其他工具手工使用。未来视频生成 API 适配器是独立模块，不作为此阶段的前置依赖。

## 4. 贯穿全流程的资产管理（横向能力）

**已确认的阶段边界**：资产管理不是独立的线性必经阶段；A3–B4 均可以逐步创建、完善或引用角色、场景、服装、道具等创作资产；B2 负责制作拆解和本集资产核对，而非独占资产创建。**资产版本、分集使用及覆写机制仍是推荐设计**，详见 [创作资产模型草案](./creative-asset-model-and-use.md)。

| 类别 | 候选内容 | 主要消费阶段 |
|---|---|---|
| 角色 | 身份、关系、人物性格、外观、表情、肢体、服装状态、参考图 | A3/A4/B1/B2/B3/B4 |
| 场景/地点 | 环境描述、空间布局、光线与风格、参考图片 | A4/B1/B2/B3/B4 |
| 道具/服装 | 外观、状态、与人物或剧情事件的关联 | B2/B3/B4 |
| 项目风格 | 题材、画风、色彩、摄影、统一画面基准 | A2–B4 |
| 参考素材 | 图像、声音设定或其它辅助媒体的引用与说明 | B1–B4 |

**已确认边界**：项目创意点子和方向严格项目内管理；项目基础角色/场景资产可被同项目不同分集复用，各分集允许明确的造型/服装/状态变体且不直接改变项目基础定义。参见 [ADR-0015](../adr/0015-project-assets-with-episode-variants.md)。镜头覆盖和媒体路径等实现仍待细化。

## 5. 阶段 Handoff 合同：系统保证什么、Agent 做什么

### 建议最小字段（逻辑合同，不是数据库 Schema）

~~~yaml
project_id: project-01
episode_id: ep-07
stage: B3_storyboard
task_scope:
  segment_ids: [P03, P04]
pinned_approved_inputs:
  screenplay: {artifact_id: script-07, revision: v3}
  director: {artifact_id: director-07, revision: v2}
  breakdown: {artifact_id: breakdown-07, revision: v1}
mandatory_constraints_summary:
  - 使用项目内已确认的视觉风格
  - 保持本集角色外观和关系一致
expected_outputs:
  - shot_plan
available_queries:
  - get_scene_by_id
  - get_segment_by_id
  - get_asset_by_id
~~~

**确定性的责任分工**：

| 责任 | 系统代码 | Agent / Skill | 用户 |
|---|---|---|---|
| 确认当前项目/分集/阶段 | 是 | 可阅读 | 可导航 |
| 判断上游是否已定稿、锁定版本 | 是 | 不自行裁决 | 可查看 |
| 读取指定场次/片段/素材 | 受控查询接口 | 按需调用 | 可在 UI 查看 |
| 编写创意、剧本、镜头、提示词 | 提供结构合同 | 负责创作 | 可反馈修改 |
| 结构性校验 | 是 | 协助修复 | 查看结果 |
| 创作质量审查 | 呈现建议与问题 | 可提出建议 | 最终判断 |
| 保存草稿、定稿、版本引用 | 是 | 通过业务服务提交 | 确认定稿 |
| 上游更新后的依赖提醒 | 是 | 不自动重做 | 选择沿用/修改 |

### 程序级正式门禁

- A2 → A3：用户选择方向并决定创建分集；A1/A2 是项目级创意活动，不强制创建“点子定稿阶段”。
- A3 → A4：故事完整产物完成用户定稿。
- A4 → B1：剧本完整产物完成用户定稿。
- B1 → B2：导演方向完成定稿（阶段拓扑为建议）。
- B2 → B3：制作拆解和片段引用完成定稿（阶段拓扑为建议）。
- B3 → B4：镜头规划完成定稿。
- B4 → 导出：镜头级提示词及整集清单可追溯、完成用户确认。

**重要**：根据已有 ADR，不允许将上游未定稿的内容作为正式阶段输入。用户依然可以自由讨论未来想法，但讨论不能直接成为提前生效的正式下游产物。

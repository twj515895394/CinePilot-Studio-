# 创作资产体系设计：项目内复用、分集使用与镜头引用

> 版本：0.1（领域与产品交互草案）  
> 日期：2026-10-30  
> 状态：B2 独立 + A3–B4 横向资产管理**已确认**；项目/分集复用与覆写方案为**推荐设计，待确认**。  
> 上游：[八阶段合同](./stage-contracts-and-artifact-map.md)、[整体系统总览](./overall-product-workflow-and-system-map.md)、[ADR-0014](../adr/0014-production-breakdown-with-cross-stage-assets.md)

## 1. 为什么需要一套统一的创作资产体系

同一项目可能有多集独立短视频，反复使用相同的拟人化角色、办公室、道具与视觉风格。若 A3 故事、A4 剧本、B1 导演、B2 拆解、B3 分镜和 B4 提示词各自将角色外观重新写一遍，容易产生漂移；如果全部依赖上下文一次传给 Agent，又回到上下文臃肿的问题。

目标是：**把可识别的设定从一次对话变成有身份、可查看、可引用的项目资产**，让不同阶段按需读取当前任务所用资产，不把所有背景资料都塞进 Handoff。

资产管理是**跨阶段能力**，不是“第九个必须完成的线性阶段”。在 A3 可以创建角色卡，A4 补充情节相关状态，B1 补充表演和视觉意图，B2 核对本集使用清单，B3/B4 以指定资产与约束完成镜头和提示词。

## 2. 已确认的边界

- **B2 是独立的制作拆解阶段**：有自己的正式产物、用户审阅节点和 B2 → B3 正式 Handoff。
- A3–B4 可以逐步创建、完善、引用角色、场景、服装、道具、风格等资产，不能规定“仅 B2 才可维护资产”。
- 项目创意点子和方向与分集的生命周期、镜头叶级归属、来源剧本场次、版本审批、精简 Handoff 与数据存储分工仍遵循既有 ADR。
- V1 不执行实际视频生成；资产可以引用用户导入的图片，不要求每个资产在系统内通过生成 API 产生图像。
- 资产跨分集共享和覆写模式**尚未由用户确认**，不把下述推荐模型直接视为事实。

## 3. 候选资产分类与职责

| 资产类型 | 主要资料 | 常见使用阶段 | UI 表现 |
|---|---|---|---|
| 角色 Character | 基础身份、性格/关系、外观、体型、表演特点、参考图、多视图 | A3–B4 | 角色卡、形象参考、使用记录 |
| 场景/地点 Location | 空间、布局、时间/天气/光线基准、画风、参考图 | A4–B4 | 场景卡、图片集、引用场次 |
| 服装 Costume | 外观/材质、适用角色和剧情状态 | B1–B4 | 服装变体卡 |
| 道具 Prop | 外观、所属、剧情用途、状态 | A4–B4 | 道具卡、来源片段 |
| 风格 Style | 视觉画风、色彩、光影、镜头风格原则 | A3–B4 | 项目风格规范 |
| 参考媒体 Reference | 参考图、角色四视图、场景图、分镜图等文件与说明 | A3–B4 | 图片预览、文件附件 |

**剧本场次 Scene**（文学单位）≠**地点场景资产 Location**（视觉/空间设定）≠**导演片段 Segment**（影视拆解单位），即使 UI 中一起展示也必须不同 ID。

## 4. 推荐的归属与使用关系

~~~text
项目 P
├── 角色资产 R01（项目候选主设定）
│    ├── 外观参考图 / 服装关联 / 表情设定
│    └── 资产历史版本 r1, r2, ...
├── 场景资产 L01
├── 道具资产 D01
├── 风格规范 ST01
└── 分集 EP01
     ├── 本集资产使用清单（引用或候选差异）
     ├── B2 片段 P01 → 剧本场次 S03
     └── B3 镜头 SH01 → 使用的 R01、L01、D01 及其明确版本/变体

同项目分集 EP02
└── 可以引用同一项目的 R01 / L01
    但其使用时是否允许外观变体或本集覆写，需要产品确认
~~~

### 推荐的引用策略（未确认）

1. **身份与外观分开考虑**：一名角色的基础身份稳定，但不同视频可以有不同服装、情绪、发型或道具状态；不应每次换衣服就复制一个“新角色”。
2. **项目资产负责基础定义**：相同角色和场景可在项目内多集被找到和复用，但不会自动跨项目共享。
3. **分集使用记录**：保存 EP 使用哪个资产及具体版本；必要时另存本集变体，明确变更范围。
4. **片段/镜头引用**：片段说明出现的角色与场景，镜头记录实际使用版本及状态；镜头不持有一份重复可编辑的权威角色描述。
5. **引用已定稿而非隐式使用最新版本**：一旦分镜/提示词定稿，它们必须能回溯当时参考的资产版本。是否允许特殊“跟随最新”使用模式留待后续。
6. **文档不等于全上下文**：Handoff 只带本次任务的资产 ID、版本和必须遵守的关键约束；Agent 再按需查询相关角色或场景细节。

### 具体例子

项目“拟人化狗狗短片”有固定角色 R01（警犬拟人形象）。EP01 是办公室故事，R01 穿衬衫、领带；EP02 是科幻故事，同一角色穿未来制服。我们希望保持基础面部/体型一致，并能明确本集服装变体，而不是让两集改变同一份可变角色外观，或让 Agent 根据旧聊天自行猜测。

## 5. A3–B4 的资产创作与消费链路

| 阶段 | 可以如何使用资产 | 产物的引用要求 |
|---|---|---|
| A3 故事 | 新增角色、定义关系与性格、草拟世界观 | 记录角色与故事节点关联；视觉细节可逐步完善 |
| A4 剧本 | 明确场次出场人物、地点、重要道具 | 结构化场次引用角色/地点资产 ID，不混淆剧本场次和地点 |
| B1 导演 | 确定角色表演风格、色彩光影、场景视觉重点 | 导演视听规范引用有效风格与相关资产 |
| **B2 拆解** | 核对每个片段需要的角色、地点、服装、道具及缺口 | 正式输出片段/子片段与资产需求及引用清单 |
| B3 分镜 | 按镜头确定人物、地点、服装、表演状态、参考图 | 镜头引用明确资产/版本，避免自由文本重复造身份 |
| B4 提示词 | 按镜头读取必要外观、动作、风格与连续性约束 | prompt 与生成准备包保留资产引用和上游镜头来源 |

## 6. Vue 工作台和 Electron 桌面版如何使用

- **项目级资产页面**：按角色/地点/风格/服装/道具分区，卡片、详情、上传参考图、查看已使用分集（项目级共享为建议，未批准）。
- **分集资产侧栏**：筛选该集使用的资产、查看引用版本、创建/选择当前集变体（变体能力待确认）。
- **B2 制作拆解页**：一侧剧本场次，一侧导演片段/子片段树，中部展示片段需求、未绑定的资产和冲突；允许用户/Agent 补齐后定稿。
- **B3/B4 编辑区**：镜头卡片/提示词面板能打开所引用角色或场景详情；编辑镜头描述不应默默改动共享资产身份。
- **通用版本审查**：资产定义变化后应能追查既有分镜引用的是哪一版，不自动覆盖已定稿分镜。

Python 统一业务服务负责实体/关系/状态，Markdown 负责描述性正文，JSON 负责结构化资产字段，SQLite 负责对象与版本索引；图片作为独立媒体文件由业务服务管理。上述仅是遵循已确认权威分工的草案，不固定具体 Schema、框架和 Electron 本地服务打包方式。

## 7. 为什么不把资产定稿与 B2 完全绑定

- 故事阶段可能早就确定角色身份，剧本阶段可能确定服装状态，导演阶段才建立视觉风格。
- B2 可形成**本集制作资产需求与使用清单**，但不应成为唯一允许创建和审核人物/场景资料的入口。
- 资产不完整时，B2 应展示缺口供用户补充；具体哪些缺口会阻断 B2 定稿，由后续阶段合同和验收标准确定。
- 这样分镜 B3 面对的是有来源的“导演片段 + 资产引用”，而不是难以核验的散乱对话。

## 8. 下一项值得用户确认的产品边界（只问一个）

**同一项目的角色/场景资产应如何在不同分集中复用？**

- **A：项目统一资产，分集仅引用，不允许覆写**。最简单，视觉规范强；但分集中的换装、不同世界观状态需要另建资产。
- **B（推荐）：项目级基础资产 + 分集显式使用/变体**。角色身份/基础视觉保持稳定，分集可选择该资产的明确版本，并在不改动项目基础定义的前提下增加服装、造型、状态等局部变体；下游镜头引用具体版本/变体。
- **C：每集复制自己的资产**。分集最自由，但项目内角色长期一致性、维护和版本回溯都容易漂移。

推荐 B，因为它在保持项目角色一致性的同时允许每集剧情造型变化。此选择只关乎**项目内**，不涉及跨项目共享库、全局资产平台或自动同步。
